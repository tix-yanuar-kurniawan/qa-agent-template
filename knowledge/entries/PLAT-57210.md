# PLAT-57210 — Dynamic Information for Passport Renewal
> **Related:** [[PLAT-52094]] · [[PLAT-57790]] · [[PLAT-57610]] · [[PLAT-57212]] · [[PLAT-57214]] · [[PLAT-57211]] · [[PLAT-57213]] · [[PLAT-57206]] · [[PLAT-57209]] · [[PLAT-57689]] · [[PLAT-52095]]

## PRD Summary

Surface an article on renewing a passport, directly from tiket.com, to users
whose stored passenger passports are expiring or already expired.

Two surfaces, two rules:

- **Profile List** (`[FE]`/`[Android]`/`[iOS]`/`[BE]` Profile List stories) — if
  the user has **at least one profile whose Indonesian passport expires within 7
  months, or has already expired**, replace the existing profile-list banner with
  passport-renewal information linking to
  `https://www.tiket.com/id-id/stories/tips/cara-membuat-paspor-dan-visa-luar-negeri`.
  Otherwise show the existing banner.
- **Edit Profile** (`[FE]`/`[Android]`/`[iOS]` Edit Profile stories) — when the
  user opens an existing profile whose passport expires within 7 months or has
  already expired, show information on updating the passport plus a redirect to
  the same article.

The decision matrix in `PLAT-57790` and `PLAT-57610`:

| Case | Issuance = Indonesia? | Show renewal banner? |
|---|---|---|
| 1 profile with expired passport | yes | **yes** |
| 1 profile expiring ≤ 7 months | yes | **yes** |
| 1 profile with expired passport | no | **no** |
| 1 profile expiring ≤ 7 months | no | **no** |
| 1 expired (ID) + 1 expiring ≤ 7 months (non-ID) | mixed | **yes** |

## Figma Design Summary

Same
`-SSoT- Passenger Data` file that [[PLAT-52094]] used, node `2623-70595`.

- **Profile list** (`Save Passengers Data` / `Simpan Data Penumpang`): an
  **amber banner with a warning icon** sits above the profile rows, reading
  `Easy steps to renew your passport.` with a `See how` link on EN, and
  `Cara mudah perpanjang paspormu.` with `Lihat caranya` on ID. It occupies the
  slot the existing banner used.
- **Profile rows** carry a red state chip. Two distinct states are drawn:
  `Passport expired` / `Masa berlaku paspor habis`, and *expiring soon*.
- **Profile detail**: the renewal information renders **inside the Travel
  Documents section, against the Passport entry**, which itself shows a red
  `Passport expiring soon`. It is scoped to Passport — Driver's License and
  Frequent Flyer entries are untouched. Four desktop variants exist
  (EN / ID × expiring / expired).
- A `Push Notif` frame sits on the same page; that is [[PLAT-52094]]'s scope,
  not this epic's.

## Key Learnings

- **`PLAT-57790` "[FE] Country Issuance Logic" is a late narrowing of the whole
  epic, and it is the reconciliation that matters.** The four original Profile
  List stories (`PLAT-57212`, `PLAT-57211`, `PLAT-57206`, `PLAT-57610`, all in
  the `839xxx`–`842xxx` id range) say only *"at least 1 profile which passport is
  going to be expired"*. `PLAT-57790` — id `844398`, so materially newer — says
  *"at least 1 profile which **Indonesian** passport"* and adds the matrix that
  makes non-Indonesian issuance a hard **no**. Reading the older stories
  alone would show the banner for any passport, which is now wrong.
- **The two halves of the epic disagree and nothing marks which is live.** The
  Edit Profile stories (`PLAT-57214`, `PLAT-57213`, `PLAT-57209`) carry **no
  country condition and no matrix**, while the Profile List half is gated on
  Indonesian issuance. This is the `[BE]`+`[FE]` mirror-drift pattern showing up
  across *surfaces* instead of across platforms. Which half is live is
  unconfirmed, because an ungated detail page shows an article
  about obtaining an **Indonesian** passport to someone holding a foreign one.
- **"7 months" is inherited, not restated.** This epic never converts it to days;
  [[PLAT-52094]] defined it as exactly **210 days** (30 days per month). The
  definition is carried over unconfirmed — an improvement epic read in isolation
  can encode stale values.
- **[[PLAT-52094]] and this epic disagree on the expired case, and this epic
  wins.** [[PLAT-52094]] has the *expiring soon* warning **disappear**
  once a passport has actually expired, replaced by an "Expired" status. This
  epic explicitly includes *already expired* in the population that gets the
  renewal banner. Both can hold — the expiring-soon chip flips to an expired chip
  while the banner still shows — and the design draws exactly that pair of chips.
- **The article URL is hardcoded to `/id-id/`.** An EN-locale user following
  `See how` lands on an Indonesian-language article.
- **"The existing banner" is never defined.** Neither the epic nor any child
  says what the pre-epic profile-list banner contains.
- **Four platforms, one behaviour.** `Responsive`, `Android App`, `IOS app` and
  `Backend` children all implement the same rule.
