# PLAT-54055 — [BE] Dynamically show mission in homepage to support Welcome Rewards
> **Type:** Story · **Status:** Done · **Priority:** Medium · **Parent:** [[PLAT-54052]]
> **Related:** [[PLAT-54052]]
> **Jira:** https://borobudur.atlassian.net/browse/PLAT-54055

## Summary
This backend story enables Loyalty to return eligible missions to Discovery when Discovery sends `account_id`, `template_code`, and `sectionId`. Loyalty evaluates eligibility, filters by `template_code`, and returns only missions the user is eligible for with all required content fields. Phase 1 MVP supports `BANNER_CAROUSEL_V2` template, returning all eligible missions sorted by dynamic end date first then nearest claim end date ascending.

## Key Points
- Discovery sends `account_id`, `template_code`, and `sectionId`; Loyalty returns only eligible missions with required content fields for Discovery rendering.
- Mission validity: only return missions that have not reached claim end date.
- Segmented missions (CDP, Mixpanel Cohort, Dynamic segment) returned only if `account_id` is eligible; global missions configured for all users always returned.
- Phase 1 MVP: `template_code = BANNER_CAROUSEL_V2` returns all eligible missions; sorting: missions with dynamic end date first, then by nearest claim end date ascending.
- Each mission requires 4 image variants (Web ID/EN, Mobile ID/EN) with Mobile ratio 5:2 and Web ratio 2:1; mandatory core fields include mission link, login state visibility, Section ID, and Chips (No chips, Locked).
- Background configuration toggle (On/Off): if ON, admin configures Color (HEX) or Image (max 1 MB).
- Response fields per mission: `account_id`, `section_id`, `images` (web_id, web_en, mobile_id, mobile_en), `mission_link`, `login_state`, `section_title` (if available), `background` (type: color/image/none, value).

## Details
### **Given**

Discovery sends:

* `account_id`
* `template_code`
* `sectionId`

### **When**

* Loyalty evaluates mission eligibility for the given `account_id`
* And filters missions based on the requested `template_code`

### **Then**

* Loyalty returns only missions that the user is eligible for
* And each mission includes all required content fields to be rendered by Discovery

## **Additional Details**

## **1. Eligibility Rules (Priority Order)**

### **Mission validity**

* Only return missions that have **not reached claim end date**

### **Segmented missions**

Missions tied to:

* CDP
* Mixpanel Cohort
* Dynamic segment

→ Only returned if `account_id` is eligible

### **Global missions**

* Missions configured for **all users**
* Always returned for all users

### **Example**

* User A → eligible for Mission 1, 2, 3
* User B → eligible for Mission 1, 2

**Response:**

* User A → Mission 1, 2, 3
* User B → Mission 1, 2

## **2. Template-Based Filtering (Scalability Design)**

### **template_code**

Determines which missions should be returned

### **Phase 1 (MVP)**

**Supported template:**

* `BANNER_CAROUSEL_V2`

**Behavior:**

* Only return mission assets if `template_code = BANNER_CAROUSEL_V2`
* Return **all eligible missions**

### **MVP Sorting Logic**

Missions will be ordered as follows:

1. **Missions with dynamic end date first**

    * Missions using dynamic mission days are prioritized

2. **Then sort by nearest claim end date (ascending)**

    * Earlier claim expiry shown first

### **Phase 2 (Future, out of scope)**

Support multiple template codes (e.g., card, widget, etc.)

Each template can define:

* Max number of missions (e.g., top 1–2)
* Ranking / prioritization logic
* Different mission selection rules

## **3. Mission Content (from Mission Dashboard)**

Each returned mission must include:

### **A. Images (Mandatory)**

Each mission will have **4 image variants**:

* Web – Bahasa Indonesia
* Web – English
* Mobile – Bahasa Indonesia
* Mobile – English

**Specifications:**

* Mobile ratio: **5:2 (locked)**
* Web ratio: **2:1 (locked)**

### **B. Core Fields (Mandatory)**

* Mission link (redirection link, auto generated)
* Login state visibility:

    * Login / Logout / Both

* Section ID

    * Used by Discovery to determine placement

* Chips

    * No chips (Locked)

### **C. Optional Fields**

* Section title (EN & ID)

### **D. Background Configuration (New)**

* **Toggle: Background On / Off**

If **ON**, admin can configure:

1. **Color**

    * Input via color code (e.g., HEX)

**OR**

2. **Image**

    * Upload background image
    * Max size: **1 MB**

## **4. Final Response Fields to Discovery**

Each mission object should include:

* `account_id`
* `section_id`
* `images`:

    * web_id
    * web_en
    * mobile_id
    * mobile_en

* `mission_link`
* `login_state`
* `section_title` (if available)
* `background`:

    * type: `color` / `image` / `none`
    * value: color code or image URL
