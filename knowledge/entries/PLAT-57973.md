# PLAT-57973 — Mission Auto-Enroll via URL Query Parameter
> **Related:** [[PLAT-57782]] · [[PLAT-57971]] · [[PLAT-34075]] · [[PLAT-56247]] · [[PLAT-58525]]

## PRD Summary

Users today must tap **Enroll** on a mission page before they can see progress
and rewards. Eligible transactions made *before* enroll are counted immediately
once they join, so a user arriving from email, push, or a campaign still hits
an extra tap. This epic adds **auto-enrollment** when a mission page URL
carries `auto_enroll=true`: if the logged-in user is eligible, they are
enrolled before the page is shown and the **success enroll bottom sheet**
appears, so already-earned progress and rewards are visible at once.

Auto-enroll reuses the **same eligibility check as manual enroll** (mission
active; user not already ACTIVE / COMPLETED / CLAIMED; quota not exhausted;
user meets targeting). Guests are not enrolled — the page stays in its normal
logged-out state. Already-enrolled users and any other blocking mission state
see the current status as-is. A **user-segment miss** shows the ineligible
state. Refreshing with the same param must not create a second enrollment.

Child stories: [[PLAT-57971]] `[FE]` Ready for QA (Responsive) holds the live
work. [[PLAT-57782]] `[BE]` is **Invalid** — no new backend story; FE calls
the existing enroll path.

## Key Learnings

- **No Figma link** on the epic or either child story. Sheet copy, ineligible
  copy, and the exact logged-out page are not specified; the AC only names
  "success enroll bottom sheet", "ineligible state" and "normal logged-out
  state".
- **[[PLAT-57782]] is Invalid**, so there is no new BE contract. How to
  reach un-enroll, prior progress, COMPLETED / CLAIMED, segment miss, ended and
  quota-exhausted states is `UNKNOWN`.
- **`targeting` vs `user segment` is one gate written twice.** The flow says
  a segment miss shows the ineligible state; the business-rules bullet lists
  "user doesn't meet targeting" under as-is. Treated as the same segmented
  miss (ineligible state), not two gates.
- **[[PLAT-56247]] split two success sheets** (Success Enroll vs Success
  Enroll + Progress) when unenrolled users already have stamps. This epic
  only names "success enroll bottom sheet".
- **Public mission URL** from [[PLAT-34075]] is `tiket.com/mission/[slug]`.
  With the locale prefix the entry point is
  `/<locale>/mission/<slug>?auto_enroll=true`.
- **Guest → login is UNKNOWN.** The AC only says guests do not auto-enroll.
  Whether login reloads the page and keeps `auto_enroll=true` is not written.
- **Reconciled:** no change log, Q&A, or comments on the epic or children.
  No struck-through scope. BE Invalid is a work-split signal, not a
  requirement withdrawal — the FE story still owns the same AC.
- **Backend-only, not specified:** a concurrent two-tab race. The written
  idempotency rule is refresh-after-enroll.
