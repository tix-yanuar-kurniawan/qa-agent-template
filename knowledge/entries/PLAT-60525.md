# PLAT-60525 — [BE] Integration Testing: Trip View Rewards Rule Configuration and Disbursement via Rewards Hub
> **Related:** [[PLAT-55753]] · [[PLAT-55759]] · [[PLAT-58532]] · [[GRA-7322]] · [[GRA-7041]] · [[PLAT-59098]] · [[PLAT-59094]]

## PRD Summary
A QA tracking story with three bullet-level ACs and no links. Trip View relies on Rewards Hub to define reward logic, calculate amounts and disburse rewards, so Loyalty BE and QA set up the rule configurations with Cross Sell and run integration tests: (1) BE creates the defined reward rules, (2) Rewards Hub calculates amounts from Trip View test transactions and disburses to test accounts without failures or discrepancies, (3) QA runs sanity checks (happy paths and edge cases) and signs off with Cross Sell. The story states no rule values, no flows and no environment. The real specification was reconstructed from the Rewards Service PRD (epic [[PLAT-55753]], stories [[PLAT-55754]] rule config, [[PLAT-55758]] instant mode, [[PLAT-55759]] pending vertical-triggered mode, and the PRD's cancel, activate, cap, fallback, idempotency and audit stories) and the Cross Sell epic [[GRA-7322]] (Trip View Cross-sell Reward Flow) with [[GRA-7041]] (Progress Complete landing page and trip states).

## Key Learnings
- **The story is a pointer, not a spec.** "Defined reward rule configurations" is never defined here. Every rule ID, campaign ID, outcome, quota, cap and fallback is `UNKNOWN`; the configured values must come from Loyalty BE.
- **Which disbursement mode Trip View uses is not written anywhere.** [[PLAT-55759]] gives Trip View as its example (3rd order pending, activate on settle, cancel on refund), while [[GRA-7884]] adds a scheduler for the landing-page claim. Whether disbursement happens at claim or by the scheduler is therefore `UNKNOWN`, and Trip View may not use instant mode at all.
- **Reconciled against later changes.** [[PLAT-58532]] (done after the PRD draft) changed a cancelled vertical-triggered record from `DONE` to `CANCELLED`, so a cancel now yields `CANCELLED`. The PRD calls the activated state `injected` while the same story family uses `DONE`; the spelling is unresolved.
- **Dropped as out of scope.** Pending date-triggered mode (PRD marks it Out of Scope), the admin dashboard (BE config only), and post-disbursement refund or claw-back. The PRD's own AC contradicts itself once: execute validates `baseValue ≤ Quota`, yet the fallback story pays a fallback when remaining quota is lower than the calculated injection.
- **The Trip View UI entry path is not given anywhere** (`UNKNOWN`). Trip View and the points pending tab are visible in the app.
- **Quota exhaustion** is the one state reachable by configuration: the PRD allows the quota to be decreased through BE config.
- **Cross-flow questions.** (1) A campaign linked to a Trip View rule is an API-type campaign; the Mission reward dropdown lists API-type campaigns that are unused, so whether a rule marks its campaign as used is `UNKNOWN`. See [[MissionConfigRewardForm]]. (2) [[PLAT-59094]] puts Rewards Hub credits behind an FDS pre-check; where the check fires (pending, activate or both) is `UNKNOWN`. (3) Trip View stamp progress, the Toggle for Stamps Mission ([[GRA-8091]]) and the landing-page APIs ([[GRA-7969]]) are other Cross Sell stories.
