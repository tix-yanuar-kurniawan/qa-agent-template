# PLAT-52851 — [BE] Bonus Point Consumer (RabbitMQ) – PNV Fallback Handling
> **Type:** Story · **Status:** Invalid · **Priority:** Medium · **Parent:** [[PLAT-52850]]
> **Related:** [[PLAT-52850]]
> **Jira:** https://borobudur.atlassian.net/browse/PLAT-52851

## Summary

When a bonus point injection is consumed via RabbitMQ and PNV status retrieval fails for a single user after retry, the consumer should fallback to treating the user as non-PNV and allow BCA to resend the bonus points in the next batch. This fallback applies only to bonus points, must not block other users in the same batch, and status must be traceable in logs for audit.

## Key Points

- When PNV status retrieval fails after retry for a bonus point injection via RabbitMQ, fallback to treating user as non-PNV.
- Allow BCA to resend bonus points in the next batch after fallback.
- Fallback applies only to bonus points.
- Must not block other users in the same batch.
- Status must be traceable in logs for audit.

## Details
**GIVEN**
A bonus point injection is consumed via RabbitMQ
And PNV status retrieval fails for a single user

**WHEN**
The consumer cannot resolve PNV status after retry

**THEN**
Fallback to treating the user as **non-PNV**
And allow BCA to resend the bonus points in the next batch

**Additional Details**

* Fallback applies only to bonus points
* Must not block other users in the same batch
* Status must be traceable in logs for audit
