# PLAT-61694 — Welcome Rewards: Handling Existing Params in URL
> **Related:** [[PLAT-61690]] · [[PLAT-61691]] · [[PLAT-61692]] · [[PLAT-61693]] · [[PLAT-63057]] · [[PLAT-53961]] · [[PLAT-55268]] · [[PLAT-56907]]

## PRD Summary
The Grand team found that URL params carried by users arriving from TikTok hotel ads were lost
once the user passed through Welcome Rewards. Requirements (identical across the epic and all
four dev stories):

1. A user arriving at Welcome Rewards with params keeps **all** of them — applies to the
   Welcome Rewards **bottom sheet** and the **homepage** section.
2. Scope includes, but is not limited to, `utm_source`, `utm_medium`, `utm_campaign`,
   `utm_external`, `utm_id`, `utm_term`.
3. If Welcome Rewards assigns a new param on entry, it is **appended** without replacing or
   removing existing ones.

Child stories: [[PLAT-61692]] `[FE]` Responsive (Ready for QA), [[PLAT-61693]] `[BE]` Backend,
[[PLAT-61690]] `[Android]`, [[PLAT-61691]] `[iOS]` (all Dev Done), [[PLAT-63057]] `[QA]`.
The Android and iOS stories add a dev note: **`token` must be excluded** because the gateway
checks it for authorization.

## Key Learnings
- **The epic never names the param Welcome Rewards assigns** (requirement 3), nor what happens
  when its key collides with an incoming one.
- **`token` exclusion is app-only in the source.** It appears on the Android and iOS stories,
  not on FE/BE. Whether web also strips `token` is an open
  question for the PM.
- **The iOS story's Platforms field says `Android App`** — a Jira data slip.
- **Surfaces follow the earlier phases:** the bottom sheet is the app onboarding surface
  ([[PLAT-53961]]), the homepage "New user exclusive" section is web-only and its **See All**
  opens the Welcome Rewards pop-up ([[PLAT-55268]]).
- **Preserving params must not break config selection by `utm_source`** (Campaign ID > UTM >
  Default from [[PLAT-53961]]).
- **[[PLAT-55268]] mentions a controller cache on the Welcome Rewards API.** If the BE now
  builds per-visitor redirect URLs, a cached response could leak one visitor's UTM values to
  another.
- **The app link format that carries params into the apps is unstated.**
- **Login round-trip is unnamed in the source.** Per the load-time param heuristic, the
  login return is not assumed to keep the query string.
- No Figma link on the epic or stories; the surface is attribution, and
  nothing here moves money or saved data.
