# PLAT-56702 — Mission Homepage Banner: Multi-Section ID Mapping
> **Related:** [[PLAT-56707]] · [[PLAT-56708]] · [[PLAT-57092]] · [[PLAT-54052]] · [[PLAT-56234]]

## PRD Summary
Mission banners currently bind to a **single** Section ID, limiting a mission to one homepage slot. This epic lets operators register **multiple Section IDs** under one banner config and builds the Loyalty-side mapping that resolves each Section ID to the right asset based on the **template code Discovery supplies per request** at render time:
- Template code `Banner Carousel` → Loyalty forwards the **uploaded banner image(s)** for that config.
- Template code `Dynamic Widget` → Loyalty forwards the **mission dynamic widget URL** `https://www.tiket.com/{locale}/dynamic-content-module/mission/{mission slug}`.

Key rules: Section ID is a **repeatable list** (add/remove); the template code is **not stored** by Loyalty (supplied per request); all Section IDs inherit the **same parent mission**, so `{mission slug}` is derived from that mission. Goal: flexible, reusable mission banner placement across the homepage without duplicating config. Extends the homepage mission work in [[PLAT-54052]] (Discovery↔Loyalty, `section_id`, `template_code`) and the Section-ID-scoped config in [[PLAT-56234]].

**Child stories:** [[PLAT-56707]] `[BE]` Configure multiple Section IDs (Backend), [[PLAT-56708]] `[Panel]` Configure multiple Section IDs (Panel - dWeb), [[PLAT-57092]] `[QA]` Test (Multi-Platform, no ACs).

## Key Learnings
- Resolution is driven **only** by the per-request template code — not stored, and **not** by Section ID naming (a `HP_BANNER_*` ID sent with `Dynamic Widget` returns the widget URL).
- One config, many slots: the reusability goal means a single mission config serves multiple homepage slots via its Section ID list — no duplicated mission configs.
- Widget URL slug always derives from the **parent mission**, identical across all Dynamic Widget Section IDs in the config.
- **Doc inconsistency found:** epic/story body text uses locale `en-id` in the widget URL template, but the worked example table uses `id-id`. Confirm intended locale with the team.
- Section-ID-scoped behavior already established in [[PLAT-56234]] (section background stored at Section ID level, latest-write-wins) — reuse that mental model when reasoning about multiple missions sharing a Section ID.
