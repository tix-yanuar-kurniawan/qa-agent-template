# PLAT-61695 — Profile: Manage Empty Last Name

## PRD Summary

A follow-up to [[PLAT-59157]] (mononym checkbox on the passenger profile). When the
user sets the last name to empty:

1. The last-name text field is **hidden** (child stories: "previously it was disabled").
2. The client tells the backend that the last name is **intentionally** empty.

Children: [Android] PLAT-61677 and [iOS] PLAT-61678 are Product Done; [FE]
PLAT-61679 and [QA] PLAT-62293 are TODO (as of 2026-10-29). There is no `[BE]` child.
The API contract is only a Slack thread linked from the Android/iOS stories, so it could not be read.

## Key Learnings

- **Hidden supersedes disabled.** The epic body and the Figma frame say disabled.
  All three client stories were edited to "hidden (previously it was disabled)", and the
  PM answered "hidden" on PLAT-61678 (2026-10-21). 
- **Hiding a filled field risks submitting its stale value.** The new
  "intentionally empty" signal and the hidden field must agree: editing Joe Smith → no last name must not send "Smith". A disabled field made this visible;
  a hidden one does not.
- **The passport scanner review is in scope by comment only.** The iOS story thread
  (2026-10-23): "will this include passport also?" → "if you mean passport scanner
  review, yes", with a request to add it to the description (not done yet). The [[PLAT-59738]] review: a one-word name auto-ticks the checkbox, or the user ticks it manually.
- **The design is drawn on Info Pemilik Akun, "Before UNM".** [[PLAT-59157]] scoped
  the checkbox to additional profiles .
  After UNM the owner's name is edited in Account Center ([[PLAT-59738]] notes).
  Whether it applies to the owner is open; how to get a pre-UNM account is `UNKNOWN`.
- **Field name for "intentionally empty" is `UNKNOWN`.** The contract is in Slack. 
- Records saved empty under [[PLAT-59157]] before this change may lack the new
  signal.
- Write contract / force-fill (`Joe Joe`) remains on [[PLAT-59126]].
