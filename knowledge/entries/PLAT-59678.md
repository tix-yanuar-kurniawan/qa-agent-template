# PLAT-59678 — [BE] New API for BCA Card Holder Information
> **Related:** [[UNM-3618]] · [[UNM-3525]] · [[UNMV1EntityRegistrationSubmitPOST]]

## PRD Summary
`GET /gks-unm-go-be/api/v1/entity/partnership?userId=` on
`https://service.bliblitiket.tools` returns BCA cobrand partnership data for a
UNM user. The only request input is the `userId` query param; the sample curl
has no auth or client header and succeeds without one.

On success the body is `code=SUCCESS` with `data.userId` echoed back and a
`partnerships` array. A connected BCA holder has one
`BCA_COBRAND_PARTNER` row: `action` is `MAPPED_EXISTING` or `REGISTERED`,
`status` is `CONNECTED`, plus `connectedAt`. An existing user with no
partnership still returns 200, with `partnerships: []`.

## Key Learnings
- PLAT-59678 is a title-only QA ticket. Requirements came from the queue curl
  plus two fixture notes (`mapped accountId: 101670323`,
  `registerred accountId: 101670326`). UNM-3618 on gdncomm is not reachable
  from the connected Atlassian MCP.
- **Mapped vs registered is a real contract split**, not two labels for the
  same row. `101670323` returns `action=MAPPED_EXISTING`; `101670326`
  returns `action=REGISTERED`. Both are `status=CONNECTED`.
- **Empty partnerships is SUCCESS, not 404.** `userId=101635460` (a known UNM
  user from [[UNMV1EntityRegistrationSubmitPOST]]) returns HTTP 200 with
  `partnerships: []`. A non-existent id (`999999999`) is HTTP 404
  `User not found`. Consumers that treat "no cobrand" and "no user" as the
  same will get this wrong.
- **Missing vs empty vs malformed `userId` are three messages.** Omitting the
  param and sending `userId=` both return HTTP 400 `message=Bad request`.
  Whitespace, letters, `0`, and `-1` return HTTP 400 `message=invalid userId`.
- **Leading zeros coerce.** `userId=0101670323` is looked up as `101670323`
  and returns the mapped holder. Do not treat padded numeric strings as
  invalid.
- No `X-Client-Id` (unlike [[UNMV1EntityRegistrationSubmitPOST]]).
- `serverTime` and `connectedAt` are live timestamps; the stable fields are `code`, `userId`, `partnerName`, `action`, and `status`.
- No DISCONNECTED example was supplied, so that response shape is undocumented.
