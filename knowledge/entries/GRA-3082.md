# GRA-3082 — [General] [Gamification] Berburu Tiket Murah S66 Improvement Part 2
> **Source:** Jira Epic · **Jira:** https://borobudur.atlassian.net/browse/GRA-3082
> **Related:** [[GRA-724]] · [[GRA-3099]] · [[GRA-3175]] · [[PLAT-57190]]

## Summary
Second S66 improvement epic on the [[GRA-724]] baseline, sharing the same charter as [[GRA-3099]] (game mechanics, UX, performance, promo integration) but targeting **S66** generally rather than a fixed launch date. Status **Done**, priority Medium, labels `Gamification` / `Growth`, reporter Novita Olivera, created 2025-08-03, no fix version. Four child issues, one **Deferred**.

Its most consequential item is the **transaction-token popup**: users were being credited tokens after a purchase with **no communication at all**, so they never spent them. Part 2 adds a session-scoped popup that reports only the tokens the user has **not yet been told about**, with copy that varies by which combination of token sources contributed.

## Key Points

### BTM popup of transaction tokens (`GRA-2872`)
- **Problem:** tokens were credited in the backend after a qualifying purchase with **no push, in-app message, snackbar or email**. Users were unaware, so rewards went unused and the perceived value of the reward system dropped.
- **Fix:** after a successful transaction that credits tokens, show a **popup / bottom sheet on the gamification landing page** with the **accumulated total of transaction tokens the user has not yet been made aware of**.
- **The popup is "unaware-since-last-seen", not a running total.** PRD example:
  - 09:00 — user transacts several times, earns **20** tokens
  - 09:25 — user opens the gamification landing page → popup says **20**
  - 09:40 — user transacts again, earns **10** tokens
  - 10:00 — user opens the landing page → popup says **10**, **not 30**
- **Copy varies by token-source combination**, and the daily-free-token copy was adjusted to match. The seven documented combinations:
  **only daily · only purchase · share only · daily + purchase · daily + share · share + purchase · daily + share + purchase.**
- The whole thing is **configurable**.
- **Explicit out-of-scope / accepted edge case:** if the user already opened the mini PDP and did **not** create a new session during the transaction (e.g. using tiket on two devices), the notification is **still shown even after the user has already spent those tokens** — the copy just has to make clear the tokens came from a transaction.

### Inject tokens for churned users (`GRA-3000`)
- Token injection campaign aimed at churned users.
- **Definition of churned used here:** users who **purchased in Aug 2024** and **did not purchase at all between Sept 2024 and Jul 2025**.

### iOS webview fixes
- **`GRA-2996` (Done)** — remove unnecessary **left, right and top margins** around the main PDP content in **iOS webview**; purely visual, must not affect functionality.
- **`NCT-20085` (Deferred)** — after minimising the tiket iOS app for ~15 minutes and reopening it, webview pages such as the **BTM mini page** and the **wishlist page** render a **white page**. Expected: webview keeps correct state across minimise/restore. **Still deferred — a known open defect, not a fixed one.**
