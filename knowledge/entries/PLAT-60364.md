# PLAT-60364 — Search Profile API
> **Related:** [[PLAT-61210]] · [[PLAT-59742]] · [[PLAT-61362]] · [[PLAT-61363]] · [[PLAT-61364]] · [[PLAT-61365]] · [[PLAT-61366]] · [[PLAT-61024]] · [[PLAT-60351]]

## PRD Summary
The saved-passenger list used to stop at 1000 profiles, so a profile added after that could
not be found or selected. Epic PLAT-61210 (Limit Profile Issue Handling) shows ~10 profiles
by default, plus a total count and a search over the full set. This BE story adds
`GET /tix-profile-core/v2/profiles/b2c/search` (service TIX-MEMBER-CORE-V2; gateway
`/ms-gateway/tix-profile-core/v2/profiles/b2c/search`). It returns `data.totalProfiles` and
`data.profiles`. Params: `q`, `limit` (default 10, valid 1..500), `includeFlyer`, `showStatus`,
`source` (mandatory), and `excludeProfileIds` (added later by Family Profile). The whole active
list is cached in Redis (`PROFILE_SEARCH_DATA:{accountId}`, Base64(gzip(JSON)), TTL 180 s).
Profile create, update and delete invalidate that key.

## Key Learnings
- **Sources reconciled.** The Confluence contract is thin: params, one 200 and one 500 example.
  The subtasks hold the real rules: PLAT-61362 (validation), PLAT-61363 (cache),
  PLAT-61364 (matching/sort/limit) and PLAT-61365 (invalidation points). Dev's P0 list
  (PLAT-61366) also documents `showStatus`, which the contract does not list.
- **Contract vs GK on 2026-11-13:**
  - Missing `X-Account-Id` → HTTP 200 `BUSINESS_ERROR`/`GENERIC_ERROR` bottom sheet, not
    `UNAUTHORIZED`. This is the same pattern as check-duplicate in [[PLAT-61024]].
  - `limit=0` and `limit=-1` → HTTP 500 `RUNTIME_ERROR` "Bad Request", not 400.
  - `limit=501` → 200 `SUCCESS`, so the upper bound is not enforced.
  - `excludeProfileIds=200404200` (the primary) still returned that profile. Either the param
    is not deployed on GK yet, or the primary cannot be excluded.
  - `source` missing → 400 "Invalid request". Any non-empty source value (even `foo`) is
    accepted.
  - `%` and `<script>` as `q` return an empty list, so `%` is not a wildcard.
  - The gateway without a bearer gives 401 "Authn: Empty token".
- **Ordering is only indirectly observable.** The response has `createdTimestamp` but no
  `updateTimestamp`, so update-time order is not directly visible.
- **Out of scope:** `ageGroupCode`/`ageGroupLabel` on the search response belongs to the
  Family Profile project (task 4.1), not to this story.
