# PLAT-54052 — Dynamically show mission in homepage to support Welcome Rewards
> **Related:** [[PLAT-54053]] · [[PLAT-54054]] · [[PLAT-54055]] · [[PLAT-54189]] · [[PLAT-55154]]

## PRD Summary
Enable dynamic, personalized mission discovery on the homepage by integrating Discovery with Loyalty. Discovery sends account_id, template_code, and sectionId; Loyalty evaluates eligibility and returns eligible missions with UI assets (images in EN/ID for web/mobile), background configuration, login state visibility, and section metadata. The claim end date is changed from a fixed date to a relative N-days calculation based on the user's effective mission end date. The Panel adds new config fields for Homepage Banner (Section ID, Banner Images, Visibility, Background toggle).

## Figma Design Summary
The Figma designs show: (1) A "Reward Claim Window (Days)" input field replacing the old Claim End Date/Time fields, with a numeric input (default: 7) and helper text "Starts after mission ends". (2) A "Visibility" heading for the login state dropdown section in the mission configuration panel.

## Key Learnings
- Scope focused on Loyalty-side: BE API eligibility + Panel configuration changes
- Discovery Confluence PRD (page 4496424991) excluded from scope as out-of-scope
- The feature spans BE API (Loyalty returning eligible missions) and Panel (mission dashboard config changes)
- Claim end date calculation has three scenarios: no dynamic period, dynamic period before global end, global end override
- Phase 1 MVP only supports BANNER_CAROUSEL_V2 template code
- Mission sorting: dynamic end date missions first, then by nearest claim end date ascending
- Background configuration supports Color (HEX) OR Image (max 1MB), toggled on/off
- Panel improvements: sticky Live Preview & Steps sections, searchable Vertical & Payment Method fields
