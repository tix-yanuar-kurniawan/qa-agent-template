# PLAT-55686 — [QA] Test: UMP x UNM Integration
> **Related:** [[UNM-3352]] · [[PLAT-55939]] · [[PLAT-51101]] · [[PLAT-55940]] · [[PLAT-53933]]

## PRD Summary

UNM (Unified Notification Manager) is integrating with UMP (Unified Messaging Platform) to
leverage centralized messaging for email and SMS. The scope covers backend development on
UNM side to route messages through UMP, dashboard support to add UNM as an entity in UMP
admin panel, and cross-origin super admin access allowing tiket admins to manage UNM entity.

## Key Learnings

- UMP is a multi-tenant messaging platform already supporting TIKET and BLIBLI entities
- Known defect PLAT-55940: gateway errors (504/503) on template listing/search APIs
- PLAT-53933 (UMP whitelist improvement) established patterns for privilege-based access,
  audit logs, and confirmation popups in UMP dashboard
- Super admin cross-entity access is a new concept for UMP — tiket origin admins accessing
  UNM entity data crosses a permission boundary
- The GDN Jira (gdncomm.atlassian.net) was not accessible via MCP; requirements were inferred
  from the PLAT Jira story description and related PLAT stories
