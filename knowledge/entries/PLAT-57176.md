# PLAT-57176 — Mission Dashboard – Mission List Page Configuration
> **Source:** Jira Epic · Child stories · Confluence API docs · Figma · **Jira:** https://borobudur.atlassian.net/browse/PLAT-57176
> **Related:** [[PLAT-57174]] · [[PLAT-57175]] · [[PLAT-58350]] · [[PLAT-58627]] · [[PLAT-56247]] · [[PLAT-56341]] · [[PLAT-57060]] · [[PLAT-45655]] · [[PLAT-56234]]

## PRD Summary
The **operator side** of the Mission List Page. [[PLAT-56247]] built the consumer
page at `/id-sg/mission`; this epic gives Campaign Managers a **Mission Center**
configuration screen inside the existing Mission Dashboard so they can change the
page's **header image** and the **mission display order** without a frontend
deployment.

The epic description is a single line — every requirement lives in the child
stories, the four Confluence API contracts, and the Figma design.

Two configurables:

1. **Header Image.** Two slots, **Mobile** (838×240 px) and **Desktop**
   (1440×484 px), each up to **1 MB**, `.PNG` or `.JPG`. One asset serves both
   EN and ID. An empty slot or an unloadable asset hides the banner while the
   Mission List Page still renders normally.
2. **Mission Sequence.** A single global ordered list, reordered by **dragging
   rows**. Moving a row shifts the others so `Order` stays gapless. A newly
   created mission auto-appends to the bottom
   (`priority_rank = current max rank + 1`). The design restricts the list to
   **scheduled and live** missions.

The screen is reached from a **new entry point** — a `Mission center` button in
the Mission Config page header — and has a **view / edit** split: view mode is
read-only with an `Edit` button, edit mode swaps in `Cancel` / `Save`, drag
handles, and image delete icons.

## Key Learnings

### Source reconciliation — the banner is mobile/desktop, not EN/ID
Both child stories **and the PRD** still specify `banner_image_en` /
`banner_image_id` with "new image is served to users matching that language".
**That requirement is dead.** Four independent sources, all newer than the story
text, replace it with **Mobile + Desktop**:

| Source | Date | Says |
|---|---|---|
| [[PLAT-57174]] / [[PLAT-57175]] descriptions | 2026-07-17 11:54 / 09:14 | `banner_image_en` / `banner_image_id`, language-matched |
| [[PLAT-56341]] body + PM comment | 2026-07-17 16:39 | slots are `Web` / `App`; "1 banner will be used for both EN and ID" |
| Confluence API contracts | 2026-07-23 → 07-30 | `mobileBanner` / `desktopBanner` |
| [[PLAT-57174]] comment (Nurhidayat) | 2026-07-23 | "Banner config will be on mobile & desktop rather than en & id" |
| Subtask **PLAT-57731** (Done) | 2026-08-06 | "Current Image Config In: EN & ID → **To Be Changed to: Mobile & Desktop**" |
| Figma | ~2026-07 | `Mobile Image` 838×240 · `Desktop Image` 1440×484 |

The same asset URL serves EN and ID.

**This corrects the [[PLAT-56247]] note**, which recorded the slots as
**Web / App** from PLAT-56341's body. That body was never re-edited, but
PLAT-57731 and all three API docs land on **Mobile / Desktop**, which is also
what shipped in the design. Treat Web/App as superseded naming for the same
decision.

**The mirror-pair check found no drift this time.** [[PLAT-57174]] `[BE]` and
[[PLAT-57175]] `[Panel]` carry byte-identical descriptions, so the usual
"only one half got the late edit" trap did not apply — but *both* halves are
equally stale against the subtask and the API docs. Worth noting that the
heuristic assumes the drift is *between* the twins; here the twins agreed with
each other and disagreed with reality.

### The design carries requirements the ACs never state
- **"You can only adjust the sequence of scheduled and live missions."** The
  stories say the priority list is "a single global ordered list across **all**
  missions" and that sort order "applies across all tabs (Active, Available,
  Past)". The design restricts the *editable set* to scheduled + live. **Consequence:** if ended
  missions never appear in the sequence, nothing documented explains what orders
  the consumer History tab. 
- **Concrete image constraints** (838×240 / 1440×484 / 1 MB / PNG-JPG) exist
  only in the design. The ACs say nothing about dimensions, size or format, so the design is the only source.
- **View/edit mode and the whole Cancel path** are design-only. 
- **The `Mission center` entry point** is design-only, confirmed by the
  "Add new entry point" sticky. 

### The API contract carries the sharpest risk
`POST /tix-mission/api/admin/mission-list/banner` is **create-once**: the doc
states it "will save only one config and return success in subsequent request
**without saving its value**". A second POST returns `SUCCESS` / `data: true`
and persists **nothing** — a silent no-op: an operator's config change is lost while the panel reports success.
Only `PUT` updates. Any panel regression that switches an update from PUT to
POST fails silently, which is exactly the failure a UI test would not catch.

Two more contract facts worth keeping:
- `desktopBanner` and `mobileBanner` are **required together** on both POST and
  PUT (`BAD_REQUEST` → `["desktopBanner and mobileBanner are required"]`). This
  sits awkwardly against the story's "both slots must be configured
  **independently**" — independent *fields*, not independent *submission*.
- `GET /tix-mission/api/admin/mission/priority` returns `{id, banner, name,
  slug}` with **no rank field**; the doc says "The Order numbering should be
  handled by Front End". So the `Order` column is purely array position, and
  there is nothing server-side to assert a rank against.
- **No PATCH contract is documented.** [[PLAT-57060]] `Create API for PATCH
  Mission Priority Order` is Done but has no Confluence page and a
  title-only description, so the reorder write path was undocumented.

### Undefined values
- **The admin API host.** All four contracts document `{{HOST}}` only, and no
  environment host for `tix-mission` admin APIs is recorded in the vault. 
- **`x MB` in the error copy.** The design's size error literally reads "must
  not exceed **x** MB" with the placeholder unresolved, while the field helper
  says 1 MB. 
- **The Mission Dashboard host.** `account.test.bliblitiket.dev` (`role=superuser`) lands on `/admin/member`, confirming the `/admin/*` shape — but **Loyalty > Mission Config had not been opened there**. The surface is `Panel > Loyalty > Mission Config > Mission center`.
- **Returning a slot to empty may be impossible.** There is no delete or reset
  endpoint, and both write verbs reject a missing slot, so the empty-slot and never-configured states may only be reachable on a fresh environment.

### Scope boundaries
- **No duplicate of [[PLAT-56247]].** That epic already covers per-user eligibility ordering and the consumer banner rendering through the priority-order API. This epic closes the config → consumer loop its own AC promises ("reflects the updated configuration on the next page load").
- **No privilege is stated for the new sub-page.** [[PLAT-45655]] records privilege ID 4024 for Mission Config, but nothing in this epic states a privilege for the new Mission Center sub-page.

## Verified live — 2026-08-12

A live check of the page for the first time closed the four UNKNOWNs above.

| UNKNOWN above | Resolved |
|---|---|
| The Mission Dashboard host | **`gatotkaca.tiket.com/admin/care/loyalty/mission-config/center`** — not the guessed `account.test.bliblitiket.dev`. Login is username + password at `/admin/member/login`, **no OTP**, and the `?ref=` deep link round-trips |
| The admin API host | **`https://gatotkaca.tiket.com/ms-gateway/tix-mission/api/admin/…`**, all four endpoints reachable with the panel session cookie. Note the path is `/mission/list/banner`, not the contracts' `/mission-list/banner` |
| `x MB` in the error copy | **1 MB** — "The file size must not exceed 1 MB.", consistent with the helper text. |
| Returning a slot to empty | **Impossible.** Empty strings and omitted slots are both rejected and `DELETE` is 405. The empty state is only reachable on a freshly provisioned environment |

Contract facts the docs did not carry:

- The reorder write is **`PATCH /admin/mission/priority/reorder`** with
  `{missionId, beforeMissionId, afterMissionId}`, answered by a **sparse rank**
  (`priorityRank: 586263035904`, `rebalanced: false`). So [[PLAT-57060]]'s
  undocumented path is now known, and the "current max rank + 1" gapless model
  above is wrong for reorders — only the moved mission is ranked.
- **A drag is committed on drop, and this is intended.** Confirmed by the PM on
  2026-08-12 and recorded **nowhere else** — not on this epic, not on
  [[PLAT-57060]], not in the four Confluence contracts, and not in the Figma,
  whose edit-mode frame shows the Cancel/Save pair with no note that half the page
  ignores it. The drop does confirm itself: the success snackbar appears within
  400 ms.

  Cancel and Save govern the header image only; the sequence drop commits
  immediately, shows the success snackbar, and survives Cancel and a reload.
- **`banner_image_en` / `banner_image_id` is confirmed stale.** The consumer
  payload has no language key and one asset pair serves all four locales.
- Exact pixel dimensions are enforced (838×240, 1440×484) — an undocumented rule
  the design's error table omits.
- The create-once `POST` no-op is real: a second `POST` returns `SUCCESS` and
  saves nothing.

Still open: **the consumer order comparison** (the list is eligibility-filtered
per user, so it needs a consumer account with a known eligible set) and **RBAC**,
since no privilege is documented for this sub-page.
