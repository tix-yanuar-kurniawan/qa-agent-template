## Summary
Product and design enhancements for the **Berburu Tiket Murah (BTM)** experience — the token-driven treasure-hunt / auction game (part of the "Harta Karun" gamification family) — refreshed for the **Anniversary Campaign**. The primary goal is to align BTM with the Anniversary brand identity while improving discoverability of token-purchase options and modernizing the gameplay. **Core gameplay mechanics, backend capabilities, and existing business logic stay unchanged unless explicitly stated**; scope is primarily UI/UX refreshes, new/reusable Page Modules, and user-flow improvements, plus two backend enhancements (Product-ID token injection, standby auto-bid). Epic priority **High**, label `Loyalty`, Platform - Eiffel; status **Product Done**.

## Key Points
- **BTM game model:** users spend tokens/Tix Points to snatch/"steal" a discounted product (treasure) before a countdown/auction timer expires; tokens are obtained via Trade Points or by buying Gift-Voucher (GV) value packs that inject bonus tokens.
- **Anniversary branding refresh** ([[PLAT-57191]]): replace crochet visual style with new Anniversary assets — hero banner, gameplay visuals, and Lottie animations. Gameplay mechanics, sounds, and capabilities unchanged; keep banner dimensions/behavior/CTA and animation triggers/timing.
- **Active Products → vertical list** ([[PLAT-57194]]): replace the per-vertical horizontal carousels with a single vertically-scrollable list; remove the "Treasures You're After" section; keep vertical/category titles where configured; support up to **2 lines** of subtext; order by **product start-active date, newest first**. (Epic wording "prioritize primary/recommended products at top" is refined by the story to newest-first ordering.)
- **⚠️ "2-column grid" is wrong in the story text.** [[PLAT-57194]] says "2-column grid on mobile as per approved design", but the approved Figma and the build both render **one full-width card per row** — see the 2026-08-03 build check below. Only Active Products changes layout; **Upcoming treasures and Past treasures keep their horizontal carousels**.
- **Inventory purchase = tabbed bottom sheet** ([[PLAT-57195]]): Tab 1 **Trade Points** (unchanged), Tab 2 **Buy Voucher** (new, uses the reusable **Image with Chips (3:4)** Page Module — page module code **`GAME_GV_PACK`**, per PLAT-57195 comment 2026-07-22 by Rudy Ondolan). Voucher content fully configurable (image, title, benefit desc, cashback/benefit chips, bonus-token info, price, CTA, deep link, optional badge) — **no hardcoded voucher content**. Promotional badges supported: **Cheapest / Best Value / More Affordable** (configurable).
- **⚠️ Default-tab discrepancy to verify:** the **epic** says "no remaining points → open Buy Voucher; >2,000 points → default Trade Points", but the **story [[PLAT-57195]]** table says "**< 2,000 points → Trade Points; ≥ 2,000 points → Buy Voucher**" — these are opposite. Treat the story table as the implemented spec and confirm the intended logic with product.
- **Token Purchase CTA** ([[PLAT-57196]]): replace the "Similar Products" recommendation copy with **"Get More Tokens" (EN) / "Tambah Token" (ID)**, same position on the Gameplay page; tapping expands/opens the token-purchase section rendered with the Image with Chips (3:4) Page Module.
- **New User Onboarding** ([[PLAT-57197]]): show an onboarding banner on the Landing Page **only** to users who have never entered any BTM page; once completed/dismissed it should not auto-appear again; banner redirects to a **configurable** tutorial/Info Page URL (also needs a shareable redirect link). Onboarding teaches: hunting timer, using tokens to snatch the treasure, competing with players, winning & booking before the timer expires.
- **Gameplay improvements** ([[PLAT-57199]], per approved ProtoPie prototype): new first-time-user section introducing the **Prize Holder** mechanic (who currently holds the prize), an updated **Steal Prize** interaction, a new **wide fade transition** animation, existing sounds unchanged, new Lottie assets from Design.
- **Reusable Page Module:** the **Image with Chips (3:4)** module must be reusable across **BTM Landing Page**, **BTM Gameplay Page**, and the **Buy Voucher** tab of the Add Tokens bottom sheet — one shared component for consistency and easier campaign management. The Buy Voucher / GV-pack instance is identified by the page module code **`GAME_GV_PACK`** (source: PLAT-57195 comment).
- **BE — Product-ID token injection** ([[PLAT-57200]] BE, [[PLAT-57201]] Panel): Reward Platform today injects tokens only by **vertical**; add **TTD Product ID-level** injection (whitelist), prioritizing Product-ID config when present and falling back to vertical config (backward compatible); return the configured token amount after purchase. Example rules: **IDR 9,900 → 13 tokens; IDR 19,900 (target) → 30 tokens; IDR 49,900 → 70 tokens** (Product IDs provided separately). **Trigger = the `order issued` event**, and **there is no refund clawback** — see the 2026-08-04 open risk below.
- **BE — Auto Bid Extension** ([[PLAT-57207]], **standby / only if needed**, Medium): a service that listens to the auction WebSocket, monitors the countdown, and auto-triggers the existing **Place Bid** endpoint when the timer drops below a **configurable** threshold (resetting the countdown to extend the auction and increase Tix-Point burn); must prevent duplicate bids per countdown window, handle retries/errors, and log/monitor triggered/success/failure/duplicate events.
- **Tracker update** ([[PLAT-57208]]): update FE trackers to match the new components (spec in linked Google Slides).

- **"Existing sounds unchanged"** refers to [[GRA-3099]]/`GRA-2863`, which is where BGM and the bid / bid-stolen sound effects were introduced.

**Baseline behaviour that this epic's redesigns collide with:**

### Build check — landing page layout (2026-08-03)
[[PLAT-57194]] moved to **In QA** and a screenshot of the built landing page settled two things the written stories got wrong or left out.

**The landing page has three product sections, not one.** Top to bottom: **"Start your treasure hunt now"** (active), **"Upcoming treasures"** (with its own section-level countdown and a "Turn on the notification so you won't miss these treasures" banner + Turn on CTA), the "How to hunt and win the treasure" token-entry banner, then **"Past treasures"** (chip filter Flights / Hotels / To Dos). Active cards carry the live countdown and the orange **"Join the hunt"** CTA; upcoming cards are disabled with **"Upcoming"**; past cards are disabled with **"Long gone"**. This maps to the `GamificationCampaignsGET` payload — `activeCampaigns` (with `countDown`, `isActive`, `sessionId`), `inactiveCampaigns` (no countdown), and `chips`.

**Active Products is one full-width column, not a 2-column grid.** In the Figma SSoT the new active section (`8412:34728`, inside the EN landing frame `8412:34722`) holds **320 px-wide cards stacked at the same x** — one per row. The old design it replaces was three 330 px-tall sections of 156×250 cards laid out at x = 0/164/328, i.e. horizontal carousel rows, now hidden in the file. The build matches Figma, so **the story text is the thing that is out of step**; the wording should be corrected with Rudy Ondolan.

**The layout change is scoped to Active Products.** Upcoming and Past are structurally identical between the old landing frames (`7423:143180`, `7421:143177`) and the Anniversary one — same 156×250 card at the same carousel offsets. They inherit only the [[PLAT-57191]] asset refresh.

**Open questions raised by the screenshot** (dummy-data environment, so confirm before filing): upcoming and past cards both render a `00:00:00` timer even though `inactiveCampaigns` returns no `countDown` and an upcoming treasure should count down to its bidding start time per [[GRA-724]]; and past cards still show the live viewer count (129), which is heartbeat-driven and meaningless on an ended treasure.

### Open risk — GV-pack tokens are injected on `order issued` with no refund clawback (2026-08-04)
**Not yet answered by product. Recorded as an open risk.**

**The trigger is settled.** [[PLAT-57200]]'s implementation is the sub-task `PLAT-57526 — "Update order issued consumer to inject token for specified Product"` (**Done**, Yhose Christ Widtantio). So of the two alternatives Novita floated in the 2026-07-13 comment, **alternative 1 shipped**: injection is event-driven off the **`order issued`** event, not the daily DWH → Reward Hub batch, and not `finished`. Tokens land within seconds of issuance. This also means the trigger is the **opposite** of Top Spender's, where spending accrues only at `finished` ([[PLAT-58175]]) — an easy pair to conflate.

**Nothing reverses the tokens on refund.** Across all 15 sub-tasks of [[PLAT-57200]] + [[PLAT-57201]] there is no refund or cancellation consumer; the `dealdash_product_token` APIs are Create / Update / Get All / Get by ID / Delete, configuration only, with no reversal endpoint. Neither story, nor this epic, mentions refund, cancellation or reversal at all, and [[GRA-724]]'s token economy documents only token *sources* — the sole ways a token leaves the balance are spending it on a bid and the nightly daily-token expiry.

**Why that is exploitable rather than merely untidy.** Injection fires at `e-ticket issued`, and per the [[PLAT-58175]] lifecycle `refund` is a legal transition **out of** that same state. So: buy the IDR 9,900 pack → 13 tokens arrive in seconds → spend them on bids → refund the voucher → keep the bids and the money. And a clawback bolted on later would not fully close it, because tokens already spent on a bid are unrecoverable; it would need negative-balance handling.

**BTM is the outlier in its own family.** Top Spender 2.0's MVP does **immediate coin reversal on `REFUNDED` / `CANCELLED`** (with manual CS refunds noted as bypassing it, see [[MVP-Gamification]]) and Tiket Mission **removes the pending stamp on refund** ([[PLAT-54718]], [[PLAT-34075]]), both consuming the existing order/refund Kafka topic. The infrastructure BTM would need already exists and is already used by its siblings, which makes the omission look accidental rather than decided.

**The cheap question that may close this entirely:** is the GV package refundable at all? TTD gift vouchers are frequently non-refundable by product policy, in which case the missing consumer is harmless. Ask Alvin Setiawan / product — if the answer is "refundable", this is a fraud path to escalate.

## Key Learnings
- **Default-tab discrepancy.** The inventory default-tab logic differs between the
  epic (>2,000 → Trade Points) and story [[PLAT-57195]] (≥2,000 → Buy Voucher) at
  exactly 2,000 points; confirm the intended rule with product.
- **Token-injection precedence is the critical BE path.** Product-ID config wins
  over vertical config, with vertical as the backward-compatible fallback; the
  three spec'd IDR→token amounts are 9,900→13, 19,900→30, 49,900→70.
- **Onboarding is a once-only, first-time-user side effect** ("never entered any
  BTM page") — shown on first visit, not shown to returning users, and does not
  auto-reappear after dismissal.
- **A story's prose and its approved design can disagree, and the prose is the
  one more likely to be wrong.** [[PLAT-57194]] says "2-column grid on mobile as
  per approved design" while the design it points at is a single full-width
  column. The phrase "as per approved design" is a tell: the writer is deferring
  to the design, so read the design.
- **The landing page has active, upcoming and past product sections; the story
  names only the active one.**
- **An improvement epic read in isolation silently encodes stale values.**
  Two values (points→token rate, purchase window) were changed *late* in the
  baseline release and never restated in the improvement stories. Capture the
  predecessor release before quoting a figure.
- **A new source feeding an existing combinatorial surface re-opens it.** The
  GV-pack purchase is one new token source, but it re-opens the seven-way
  token-popup copy matrix and the daily-first spend-order rule from
  [[GRA-3082]] / [[GRA-3099]].
- **Redesigning a screen re-opens every rule that screen enforced.** The Prize
  Holder / Steal Prize rework inherits the last-bidder re-bid block, the
  ownership countdown copy, identity masking, blacklist greying, and the audio
  toggle — none of which appear in [[PLAT-57199]]'s own description.
