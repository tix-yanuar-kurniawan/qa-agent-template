# PLAT-54713 — [BE] Loyalty - Flight Hotel Bundling
> **Related:** [[PLAT-54714]] · [[PLAT-54715]] · [[PLAT-54716]] · [[PLAT-57094]] · [[PLAT-50432]] · [[PLAT-55084]]

## PRD Summary

Backend Loyalty support for **Flight x Hotel Bundling**: one Order ID can contain multiple Order Detail IDs across Flight and Hotel. Child stories cover (1) [[PLAT-54714]] points earning/injection per Order Detail ID using each vertical's rate, (2) [[PLAT-54715]] mission evaluation treating bundling as its own vertical (`Flight & Hotel Bundling`), (3) [[PLAT-54716]] refund / reschedule / rebooking for IPC and other points, and (4) [[PLAT-57094]] points-usage capping at checkout via `MAX(cap% across verticals)`. Related product epic [[PLAT-50432]]; solutioning umbrella [[PLAT-55084]]. All child stories are Backend-only. No Figma on this epic.

## Key Learnings

- **Child ACs supersede the epic intro on missions.** The epic body says the mission engine should evaluate at detail level so hotel nights can count toward a hotel mission while flight does not. [[PLAT-54715]] explicitly contradicts that: bundling is **one** vertical and must **not** be split. The hotel portion of a bundle does not count toward a hotel mission.
- **Earning and missions intentionally diverge.** Points earning ([[PLAT-54714]]) is per Order Detail ID with per-vertical rates and separate injections. Missions ([[PLAT-54715]]) treat the same order as a single bundling vertical.
- **Mission rule.** Bundling does **not** count for Flight-only, Hotel-only, or Flight+Hotel listed as separate verticals — only when `Flight & Hotel Bundling` is explicitly included. Order ID and GBV mission types are the surfaces that may use that vertical.
- **Refund/reschedule vs mission stamps.** 54715 states refund & reschedule do not issue mission stamps because the order never finishes — aligned with the tiket lifecycle (`finished` | `refund` | `reschedule` are mutually exclusive). IPC/pending reversal is covered by 54716 and still applies because IPC is credited earlier.
- **Pax-level refund = full Order Detail ID refund.** Even a 1-of-2 pax refund on a flight detail revokes the **entire** detail's IPC. There is no proportional pax IPC revocation.
- **Rebooking vs partial rebook for missions.** Rebooking revokes all original points and reinjects on the new transaction (54716). Separately, a **partial** hotel rebook can produce a new independent hotel Order ID that may count toward a hotel mission (54715) — different path from full rebooking point revocation.
- **Points capping uses MAX, not MIN or weighted average.** Flight 30% + Hotel 50% ⇒ 50% of total paid price. Single-vertical capping must stay unchanged.
