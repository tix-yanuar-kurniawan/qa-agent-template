# PLAT-52852 — [BE] Return Error & Let Caller Retry (Synchronous APIs)
> **Type:** Story · **Status:** Done · **Priority:** Medium · **Parent:** [[PLAT-52850]]
> **Related:** [[PLAT-52850]]
> **Jira:** https://borobudur.atlassian.net/browse/PLAT-52852

## Summary

For synchronous ULP/points processes that fail, the API must return a clear, actionable error response to the caller and allow the caller to retry. Failures must be logged for monitoring and audit. This applies to a defined set of synchronous APIs including Apply Point, Unapply Point, refund operations, point management, and Tech Support Dashboard endpoints.

## Key Points

- On process failure, API returns clear, actionable error response and allows caller to retry.
- Failures are logged for monitoring and audit.
- APIs covered: Apply Point, Unapply Point, Get Refund Cashback Detail, Submit Refund, Cancel Points, Refund Approval, Add Pending Point, Add Active Point.
- Tech Support Dashboard APIs covered: Delete Point, Delete Point Approval, Inject Point Approval, Create Pending Task Bulk, Admin ULP Point History, Admin Get Pending List.
- Also covers ULP Generate Token.

## Details
**GIVEN**
There are a process involving ULP/points

**WHEN**
The process fails

**THEN**

* The API must return a **clear, actionable error response** to the caller
* Allow the caller to retry the process
* Logged the failures for monitoring and audit
