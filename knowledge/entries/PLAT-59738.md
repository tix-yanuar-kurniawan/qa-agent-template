# PLAT-59738 — Passport Scanner
> **Related:** [[PLAT-60474]] · [[PLAT-60475]] · [[PLAT-60476]] · [[PLAT-60683]] · [[PLAT-60338]] · [[PLAT-60339]] · [[PLAT-60341]] · [[PLAT-60405]] · [[PLAT-60340]] · [[PLAT-60342]] · [[PLAT-59747]] · [[PLAT-57210]] · [[PLAT-52094]] · [[PLAT-59157]] · [[PLAT-60403]] · [[PLAT-61029]] · [[PLAT-61407]] · [[PLAT-61524]]

## PRD Summary
Users can fill passport details on a saved profile by scanning their passport
with the camera or by uploading an image, instead of typing every field.
PRD: [[PRD] Passport Autofill on Member Saved Profile](https://borobudur.atlassian.net/wiki/spaces/MEM/pages/4916936887/PRD+Passport+Autofill+on+Member+Saved+Profile) (v7, 2026-09-21).

The epic's own description is a copy of the Welcome Rewards epic background
and says nothing about passports. The scope comes from the child stories and the PRD:

- **Adding Scan Entry Point** ([FE] PLAT-60474, [BE] PLAT-60683, [Android]
  PLAT-60338, [iOS] PLAT-60405): an "Update required!" hint under Passenger Data
  in My Account when any profile's passport is expired or about to expire.
  Scan entry points on 5 surfaces: edit primary profile, the passport dialog on
  the primary profile, add secondary profile, edit secondary profile, and the
  passport dialog on the secondary profile.
- **Main Profile — Edit by Scanning/Uploading** ([FE] PLAT-60475, [Android]
  PLAT-60339, [iOS] PLAT-60340): name is not editable. An intermediate page
  shows guidance and a privacy-policy link. The user chooses camera or gallery,
  each behind a consent step. If the scan fails, an error is shown. If it
  succeeds, a summary preview opens with at least 4 prefilled fields, each
  editable with the edit form's validation. Confirm fills the edit form.
- **Secondary Profile — Edit/Create by Scanning/Uploading** ([FE] PLAT-60476,
  [Android] PLAT-60341, [iOS] PLAT-60342): the same flow, with 8 scanned fields
  including first and last name and date of birth.
- Upload must read the image in standard portrait (MRZ at the bottom), in
  landscape (±90°) and in reversed portrait (180°).
- **Desktop entry point** ([FE] PLAT-61029, added 2026-10-05): on desktop the
  same 5 entry points and the Update required hint exist, but clicking an entry
  point shows a **QR code** with a URL to the profile list. On the phone: app
  installed → opens the app; no app → opens tiket.com in the browser; logged in
  → profile list; not logged in → homepage (the not-logged-in lines are in red in
  the story). "Doesn't need apps development but need to register the url."
- **CEH error on the scan preview** ([BE] PLAT-61407, added 2026-10-09, Ready for
  QA): when loading the existing main profile
  (`/ms-gateway/tix-member-core/v2/account/v2/profile`) fails, any business error
  returns `GENERIC_ERROR` → a non-dismissible BOTTOMSHEET "Unable to load
  content" / "We encounter a technical issue. Please try again in a few
  moments." with "Back to previous page" (GO_BACK) and "Retry" (RETRY_API).
- **Scanner data persistence POC** ([FE] PLAT-61524, added 2026-10-09): one-line
  description; epic comment 2026-10-14 says the POC works and the current
  approach stays. No AC.
- Solution stories (PLAT-59737/59744/59747) are Done or Dev Done. The
  implementation stories are TODO or Blocked as of 2026-10-01.

## Figma Design Summary
- **Entry**: blue "Scan passport to auto-fill data" bar on Account Details (main
  profile, below the Account Center block), Passenger Detail, Add Passenger Data
  (ID: "Pindai paspor untuk isi data otomatis") and inside both Passport Details
  sheets. In My Account, the "Save Passenger Data" row shows a red **Update
  required!** badge. List rows keep the existing "Passport expiring soon" /
  "Passport expired" chips.
- **Intermediate page "Passport Scanner"**: three ticks (scan to auto-fill,
  privacy protected, images only used to fill the data and deleted once
  processed), "Scan your passport details page with the 2 lines of code at the
  bottom", "By continuing, you agree to the passport scanner's Privacy Policy.",
  Continue.
- **Consent sheets**: "tiket.com would like to access your camera" and "tiket.com
  would like to access your images", then the OS prompt. Denial is marked
  "follow existing flow & logic".
- **Scanner**: "Make sure the entire page fits in the frame." / "Hold still until
  the scanning process is complete.", gallery and flash icons, a scanning
  animation, and a red error snackbar "Unable to scan. Make sure the passport
  details page is inside the scan area." A first-use frame reads "Menyiapkan
  pemindai — Mengunduh pembaca paspor. Ini hanya terjadi sekali."
- **Logic note**: the full scan is 8 fields. All 8 read → summary with the banner
  "Please make sure the passenger data is correct to prevent any travel issues."
  4 or more → summary with "Scan result incomplete. Double-check and complete the
  data, or rescan the passport." Fewer than 4 → error snackbar on the scanner.
- **Summary "Passport Details"**: passport thumbnail (tap opens a full-image
  view). Fields: First & Middle Name, Surname/Last Name, "No surname/last name",
  Date of Birth, Sex, Nationality, Issuing Country, Passport Number, Expiry Date.
  **There is no Issue Date.** Missing fields show inline errors ("Enter the date
  of birth listed on the passport.", "Enter the nationality listed on the
  passport."). The checkbox "I have checked and made sure that all the data is
  correct." enables Confirm, which is disabled by default. Rescan.
- **Name split note**: 1 word → First & Middle, with "No surname" ticked
  automatically. 2 words → word 1 First, word 2 Last. More than 2 → last word
  Last, the rest First & Middle.
- **After Confirm**: the form is filled and a snackbar reads "Auto-fill data
  completed. Please make sure the passenger data is correct."; the user still
  taps Save.
- Main profile Account Details has **no Date of Birth or name fields** in
  Identity Info (title, Sex, Nationality, NIN). Name, phone and email are edited in the
  Blibli Tiket Account Center.

## Key Learnings
- **The epic description is the wrong epic.** It is the Welcome Rewards
  background verbatim. The real spec is in the child stories and PRD v7.
- **Which fields are scanned for the main profile differs across sources, and the
  newer stories win.** PRD v7 (2026-09-21) strikes only First/Last name for the
  main profile and still lists Date of Birth and Issue Date. [FE] PLAT-60475
  (cloned from Android PLAT-60339 on 2026-09-23) and the Android story strike
  First, Last, Date of Birth and Issue Date in both modes. [iOS] PLAT-60340
  strikes DOB only in upload mode and drops Issue Date in both. The Account
  Details design has no DOB field. The newer stories are followed (5 fields:
  Passport Number, Nationality, Sex, Expiry, Issuing Country); the iOS/PRD drift
  is `UNKNOWN`.
- **Issue Date is never scanned now**, for either profile: struck or removed in
  every story, absent from the design summary, still listed in the PRD. The
  Passport Details sheet still has an Issue Date field, so whether a new
  passenger can be saved without one is open.
- **The "8 forms" rule does not fit the main profile.** The main profile fills
  only 5 fields, so "complete" can never mean 8 there.
- **App and FE stories describe orientation differently but expect the same
  result.** FE and the PRD list three accepted orientations. Android/iOS say the
  file is rotated 90° at a time until the MRZ reads. What matters is the result
  (same values in all four orientations), not the method.
- **Design partial frame shows the full-scan banner**, while the logic note and the
  "Edit: Passport Number" frame use "Scan result incomplete…". The logic
  note is taken as authoritative. Copywriting is marked Completed, so the strings are final.
- **Privacy Policy target conflict.** The stories give
  `https://www.tiket.com/en-id/info/privacy-policy`. The design draws an in-app
  "Document OCR Filling Program" page whose placeholder body mentions Trip.com.
  The story URL is taken as authoritative.
- **Shared surface with older profile epics.** The name split ends in the
  [[PLAT-59157]] mononym checkbox (one-word name → "No surname" ticked, saved
  without a last name). Sex vs title touches [[PLAT-60403]] (apps derive
  gender from salutation). The Update required hint overlaps
  [[PLAT-52094]] (7 months = 210 days, inherited) and [[PLAT-57210]]
  (renewal banner gated on Indonesian issuance, but this hint states no country
  condition).
- **Passport-number masking in app logs** is tracked on [[NCT-22077]] (iOS) and
  [[NCT-22078]] (Android), linked from this epic. It is owned there.
- **Questions for PM/dev:** (1) Is DOB scanned on the main profile for iOS?
  (2) Is Issue Date mandatory when the scan leaves it empty? (3) What are the
  complete/incomplete thresholds for the 5-field main profile? (4) Does a scan
  started from the Passport Details sheet also fill Sex/Nationality? (5) Is
  the name split by word count or by the MRZ surname separator? (6) Does Update
  required! apply to non-Indonesian passports? (7) Does a scanned Sex change
  the title? (8) Which platform shows the first-use "Menyiapkan pemindai" frame?
- **2026-10-23 status.** PRD still v7 and no story description changed since
  2026-10-01. The new scope is three late-added stories (see PRD Summary). Most stories are now Dev Done; PLAT-60339
  (Android main) and PLAT-60341 (Android secondary) are still in development,
  waiting on the POC and the PLAT-61407 contract.
- **"Responsive" now means two behaviours.** Mobile viewport runs the scanner;
  desktop viewport shows a QR code (PLAT-61029).
- **The desktop QR design isn't approved.** The FE dev attached a proposed layout
  on 2026-10-20 and asked the PM to confirm it. The same comment says the
  story is blocked on VPN access, even though its status is Dev Done.
- **The QR link depends on URL registration, not on app code.** If the profile
  list URL is not registered as an app link, the phone opens the browser instead
  of the app. Whether it is registered on GK is `UNKNOWN`.
- **Who uses the CEH error sheet is only partly known.** Only the Android
  main-profile story says it waits on PLAT-61407. Whether Responsive shows the sheet is
  `UNKNOWN`. No fault switch is named. Retry is the only way to recover inside
  the flow.
- **Questions added:** (9) What is the exact QR URL, and is it registered on GK?
  (10) Is the dev-proposed desktop QR layout approved? (11) Does Responsive also
  show the CEH sheet? (12) What did the persistence POC (PLAT-61524) persist:
  scanned values across a reload or app kill, or the image?
