# PLAT-53429 — Mission Milestone
> **Source:** Jira Epic · **Jira:** https://borobudur.atlassian.net/browse/PLAT-53429
> **Related:** [[PLAT-34075]] · [[PLAT-45655]] · [[PLAT-56234]] · [[PLAT-54697]] · [[PLAT-54698]] · [[PLAT-54699]] · [[PLAT-54728]]

## Summary
Mission Milestone adds intermediate reward checkpoints on Stamp and GBV missions so users can unlock smaller rewards before full mission completion. Scope spans BE progress/claim/comms, consumer FE progress/rewards UI, and Panel admin config + live preview. Epic status **In Development** (Platform - Eiffel / Loyalty). Separate from Duplicate Mission [[PLAT-56234]]; they share the Mission Dashboard create/edit surface but have no Jira issue link.

## Key Points
- Problem: full-completion-only rewards create a high barrier → lower enroll-to-purchase conversion; milestones give near-term goals.
- Applies to **Stamp** and **GBV** missions (also progress UI revamp for Order ID / Room Night display unification).
- Admin can enable Milestone feature and define positions ≤ total target; **final target must always have a milestone**; one milestone per stamp/GBV value; GBV min gap **1,000 IDR**; milestones stored ascending; final milestone cannot be removed.
- Stamp missions: allow up to **500 stamps** (was 20).
- Each milestone: 1 reward (points variants or promo ID), quota, icons (milestone/reward achieved & not), quota-low visibility, reward title, PN/email toggles for progress + achieved.
- User flow: reach milestone → reward claimable → claim injects reward → status Claimed / Use Now; multi-milestone in one order requires claiming each; unenrolled eligible users can view/claim (claim enrolls).
- Comms: milestone-reached and milestone-progress PN/email (segment thresholds: first progress, 50%, 75%; priority when skipping thresholds).
- Panel stories: Configure Milestones ([[PLAT-54698]]), Live Preview ([[PLAT-54699]]); BE configure ([[PLAT-54697]]); solutioning for “Mission Milestone Dashboard & CRMs” ([[PLAT-54728]]).
- **Relation to Duplicate Mission ([[PLAT-56234]]):** no epic/story link. Duplicate copies “all mission configurations” except slug/start/end and never names milestones. Milestone stories’ “duplicate” wording means **no duplicate milestone positions**, not the Duplicate Mission feature. Soft product overlap only: both extend Mission Dashboard create/edit.

## Details

### Epic background (verbatim intent)
Current missions only reward after full completion (all stamps / full GBV). That feels too hard and hurts motivation. Milestones unlock smaller rewards at predefined progress points for Stamp and GBV missions, with configurable rewards, UI indicators, and notifications when users are near or reach a milestone.

### Configure Milestones (admin) — rules
- Enable Milestone feature on create/edit mission.
- Positions at stamp or GBV values ≤ total target; final target milestone mandatory.
- Validations: no duplicate positions, no beyond target, final exists, GBV gap ≥ 1,000, required fields complete.
- Per-milestone fields include reward type/details, quota, icons, quota visibility, title, and four comms toggles (progress PN/email, achieved PN/email).

### Live Preview
- Shows all milestones on progress bar with correct positions, achieved/not icons, reward title/label, segmentation, final-milestone distinction.
- Reflects current config without requiring backend save.

### Consumer behavior highlights
- Auto-scroll progress to latest achieved milestone (animation).
- Dynamic “book X for next reward” style progress copy for GBV / room night / stamps.
- Quota ran out is per-milestone; other milestones remain claimable.
- Claim-while-unenrolled: enroll + inject + claimed popup.
