# PLAT-55284 — [BE] Top Spender Improvement - Leaderboard Sorting
> **Type:** Story · **Status:** Invalid · **Priority:** Medium · **Parent:** [[PLAT-54035]]
> **Related:** [[PLAT-54035-v2]] · [[PLAT-54035]]
> **Jira:** https://borobudur.atlassian.net/browse/PLAT-55284

## Summary

When multiple users have the same `top spender coins` value in the Top Spender leaderboard, MongoDB returns ranking order randomly because sorting values are identical. This causes inconsistent leaderboard positions for users with equal coin totals. The objective is to improve leaderboard sorting so users with equal `total_coins` receive deterministic ranks, with the user who first reaches the coin amount receiving the higher rank.

## Key Points

- Current issue: users with identical `top spender coins` (e.g., User A and User B both at 1,500 coins) may appear in random order between requests or deployments.
- Expected behavior: the user who first reaches the coin amount receives the higher rank.
- Sort priority: `top spender coins` DESC, then `first reach at` ASC (earlier timestamp gets higher rank).
- Example: User A (1,500 coins, first reach 10:01 AM) ranks #6; User B (1,500 coins, first reach 10:05 AM) ranks #7.
- Acceptance: identical `top spender coins` are consistently ranked; earlier achiever receives higher rank; order remains stable across requests; no random MongoDB ordering for same coin totals; existing leaderboard functionality remains unaffected.

## Details
### Background

Currently, when multiple users have the same `top spender coins` value in the Top Spender leaderboard, the ranking order is returned randomly by MongoDB due to identical sorting values.

This causes inconsistent leaderboard positions for users with the same amount of coins.

Example:

* User A: 1,500 coins
* User B: 1,500 coins

Current result:

* Ranking order may change randomly between requests/deployments.

Expected behavior:

* The user who first reaches the coin amount should receive the higher rank.

[image]
---

### Objective

Improve leaderboard sorting logic to ensure deterministic ranking for users with equal `total_coins`.

---

### Proposed Sorting Logic

Sort priority should be:

1. `top spender coins` DESC
2. `first reach at` ASC
  (earlier timestamp gets higher rank)

Example:

| User | Total Coins | First Reach Time | Rank |
| --- | --- | --- | --- |
| User A | 1,500 | 10:01 AM | #6 |
| User B | 1,500 | 10:05 AM | #7 |

### Acceptance Criteria

* Users with identical `top spender coins` are consistently ranked.
* Earlier achiever receives higher rank.
* Leaderboard order remains stable across requests.
* No random ordering from MongoDB for same coin totals.
* Existing leaderboard functionality remains unaffected.
