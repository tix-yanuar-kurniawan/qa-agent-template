# PLAT-54038 — [FE] Top Spender Challenge
> **Type:** Story · **Status:** In QA · **Priority:** Medium · **Parent:** [[PLAT-54035]]
> **Related:** [[PLAT-54035-v2]] · [[PLAT-54035]]
> **Jira:** https://borobudur.atlassian.net/browse/PLAT-54038

## Summary
This frontend story implements Top Spender Challenge with manual and automatic progression criteria to boost purchases for Top Spender users. A single Top Spender Program can run multiple challenges simultaneously, each with independent Start_Date and End_Date, and challenges are automatically active within their date range without requiring a user 'start' click. Mission cards display spending targets with progress bars; completed missions automatically award bonus coins that appear in activity history.

## Key Points
- Manual challenge start initiated by clicking "Start" before it begins (per acceptance criteria); updated mechanics state challenges are automatically active within their date range with no explicit user 'start' click required.
- Challenges without progression (e.g., payment method, airline partner) and with progression (e.g., total GBV, room nights, total order count) must be clearly defined.
- Mission reward types configurable via CMS: Fixed Amount or Earn Rate + Multiplier on GBV.
- Priority 1 mission activity: Total GBV threshold (e.g., spend IDR 50M → earn 10,000 Top Spender Coins) with CTA button `Start`; Priority 2: Count of Order IDs with CTA `Book`; Priority 3: Room Nights with CTA `Book`.
- UI shows total coins earned from challenges and special partners combined; no individual icons per challenge.
- Coins from challenges must be differentiated by source and displayed to users (e.g., 'You earned 123 Top Spender Coins from completing a challenge').
- Retroactive coins for challenges are calculated only if the user joined Top Spender within the challenge's active timeframe; users joining after a challenge ends do NOT receive retroactive coins.

## Details
### Context

We would like to implement Top Spender Challenge, which involves both manual and automatic progression criteria in order to boost purchase for Top Spender users.

### Acceptance criteria

* Manual challenge start initiated by clicking **“Start”** before it begins.
* Challenges without progression (e.g., payment method, airline partner) are clearly defined.
* Challenges with progression (e.g., total GBV, number of room nights, total order count) are clearly defined.

As a Participant, I want to complete "Weekend Challenge" or "Flash Missions" so I can earn a x times multiplier for a limited time to quickly overtake my rivals on the leaderboard.

**Detailed requirement:**

* **Updated Challenge Mechanics  \[UPDATED\]**:

    * A single Top Spender Program can have more than one challenge running simultaneously.
    * Each challenge has its own independent Start_Date and End_Date.
    * Challenges are automatically active within their date range, no explicit user 'start' click required.
    * UI: No individual icons per challenge. The UI shows total coins earned from challenges & special partners combined.
    * Mission cards display specific spending targets with a progress bar. Once a mission is completed, the bonus coins are automatically awarded and will appear in activity history.

    Mission reward types  **\[UPDATED\]** (configurable via CMS — Fixed Amount or Earn Rate + Multiplier on GBV):

* Mission can also include activities such as:

    * Priority 1: Total GBV threshold (e.g., spend IDR 50M → earn 10,000 Top Spender Coins) -> Fixed amount reward.

        * Name of the CTA button: `Start`

    * Priority 2: Count of Order IDs (booking streak).

        * Name of the CTA button: `Book`

    * Priority 3: Room Nights (booking streak).

        * Name of the CTA button: `Book`

    * Nice-to-Have: Priority 4: Share link to friends/family.
    * Nice-to-Have: Priority 5: Click / Choose Product (chooseProduct).
    * Nice-to-Have: Search (searchLoaded), Visit Product Page (pageVisit), Write Product Review (requires Review BE integration).

* **\[UPDATED\]** Coins from challenges must be differentiated by source and displayed to users (e.g., 'You earned 123 Top Spender Coins from completing a challenge').
* **\[UPDATED\]** Challenge retroactive logic: Retroactive coins for challenges are calculated only if the user joined Top Spender within the challenge's active timeframe. If a user joins after a challenge has ended, they do NOT receive retroactive coins for that challenge.
