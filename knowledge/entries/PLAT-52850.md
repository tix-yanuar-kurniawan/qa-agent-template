# PLAT-52850 — [BE] Fixing Loyalty fundamental issues
> **Related:** [[PLAT-52849]] · [[PLAT-52851]] · [[PLAT-52852]] · [[PLAT-52853]] · [[PLAT-54632]]

## PRD Summary

Addresses recurring Loyalty issues where ULP returns errors during refund processing and points are not released when order IDs expire. Three main stories: (1) Cron point activation now re-reads PNV from cache per-user instead of stale RabbitMQ payload, (2) 15 synchronous APIs must return clear actionable errors enabling caller retry, (3) 11 async consumers must handle PNV failure with per-message retry, graceful failure, idempotency, and observability.

## Key Learnings

- Three distinct patterns: cron batch (per-user cache), sync API (error response quality), async consumer (per-message retry)
- PLAT-52851 was marked Invalid
- All async consumers must be idempotent — this is a cross-cutting requirement
- Retry is always scoped per-user or per-message, never per-batch
- No manual intervention should be required for transient failures
