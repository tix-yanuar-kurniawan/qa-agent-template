# GRA-3099 — [General] [Gamification] Berburu Tiket Murah S66 Improvement Part 1
> **Source:** Jira Epic · **Jira:** https://borobudur.atlassian.net/browse/GRA-3099
> **Related:** [[GRA-724]] · [[GRA-3082]] · [[GRA-3175]] · [[PLAT-57190]]

## Summary
First of two S66 improvement epics on top of the [[GRA-724]] baseline, refining game mechanics, UX, performance and promo integration for the **August 2025** relaunch (game launch **7 Aug 2025**, fix version `Grand_release_2025_August_7`). Status **Done**, priority Medium, label `qa_66`, reporter Novita Olivera, created 2025-08-04. Six child stories. Shipped as **`TIX-GAMIFICATION-NEXT-FE` BTM Improvements v1.3.0**; note the paired `TIX-GGWP-SERVER-GO` deployment (`DPL-56498`) ended in **ROLLBACK**.

The headline behavioural change is that **a user who already holds the treasure can no longer bid again** — previously they could, burning tokens for nothing. Part 1 also fixes the blacklisted-user experience on the mini PDP, reworks daily-token deduction, and adds audio.

## Key Points

### Restrict re-bidding for the last bidder (`GRA-2863`)
- **Problem:** a user who is already the last bidder could keep bidding on the same treasure, causing confusion and **pointless token burn**.
- **Rule:** if the user *is* the last bidder, **further bids are disabled** and **no token is deducted** when they try to bid again without having been outbid.
- **UI feedback:** the **Bid button is greyed out** while the treasure is still held by the current user, plus a snackbar:
  > "Harta ini masih milikmu! Kamu tidak perlu bid lagi. [Lihat cara menang]"
- A **"Cara Menang" (How to Play)** label/button is added **below the treasure chest**, linking to a How-to-Play info page.

### Dynamic ownership countdown copy (`GRA-2863`)
Above the countdown timer, the copy now depends on who holds the treasure:
- current user holds it → **"Menjadi milikmu dalam…"**
- another user holds it → **"Menjadi milik orang lain dalam…"**

### Audio (`GRA-2863`)
- **Background music** on the Landing Page and mini PDP, a **sound effect when the user places tokens (bids)**, and a **sound effect when their bid gets stolen**. Only surfaced on the mini PDP.
- A **CTA to enable/disable sound & BGM**.
- **Acknowledged platform limitation:** **iOS autoplays; Android, mWeb and dWeb do not.** This is a known-and-accepted difference, not a bug.

### Campaign end date & share copy (`GRA-2863`, `GRA-2864`)
- The campaign end date could move from **12 Aug → 31 Aug 2025**, which cascades into the **T&C** and the **WhatsApp social-sharing copy**. Product extended to live until 31 Aug 2025.
- **WhatsApp share link** updated again (separate design node).

### Blacklisted-user UX on the mini PDP (`GRA-2869` BE, `GRA-2870` FE)
- **Before:** a blacklisted user could walk from the landing page into the mini PDP untouched and only discovered the problem when they pressed Bid — they got the snackbar *"user cannot join this campaign"* **while the CTA button stayed red/enabled**.
- **After:** navigation to the mini PDP is smooth, the ineligibility is communicated **preemptively/contextually**, and the snackbar appears **with the CTA greyed out**.

### Token accounting (`GRA-3100`, `GRA-3145`, `GRA-2864`)
- **Prioritise daily-token usage.** The system had been deducting 5 tokens a day as a "daily token deduction", which was never intended — it should only deduct daily tokens and should **spend daily tokens first each day** (so the expiring balance is consumed before persistent tokens).
- **Remove the daily-token cron job** entirely (`GRA-3145`).
- **Loyalty point-deduction remark renamed `game-dealdash` → `game-btm`** (`GRA-2864`; ref Confluence *Loyalty x Growth Point Deduction Deal Dash*, page `3551821845`).
- **Share PN acceptance criterion made explicit:** when user A's shared link is clicked by user B **and B lands on the landing page in a logged-in state**, **A** receives a notification that someone clicked their link and that A earned **+1 token**.

### QA notes
- **"You already hold it" is now a first-class state** with three visible effects — disabled bid, greyed CTA, snackbar — *and* one invisible one: **no token deduction**. The token deduction is the part most likely to be overlooked and the part that actually cost users tokens.
- **The ownership copy is a two-branch string tied to live websocket state**, so it is affected whenever the gameplay page is redesigned (as [[PLAT-57190]] does with Prize Holder / Steal Prize).
- **Blacklist has two moments** — page entry and bid attempt. The fix moved the signal earlier: the CTA is greyed and entry is not interrupted.
- **Daily-first token spend order** is observable only with a mixed balance (daily + transaction/points); with a single-source balance it cannot be seen.
- **Audio differs by platform by design** (iOS autoplay only), not a bug.
