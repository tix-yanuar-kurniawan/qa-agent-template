# PLAT-60351 — Multiple Frequent Flyer in Profile
> **Related:** [[PLAT-59112]] · [[PLAT-59749]] · [[PLAT-60053]] · [[PLAT-60061]] · [[PLAT-60353]] · [[PLAT-60354]] · [[PLAT-60355]] · [[PLAT-60356]] · [[PLAT-61087]] · [[PLAT-61572]] · [[PLAT-60403]] · [[PLAT-57210]] · [[PLAT-59157]]

## PRD Summary

A profile can save only 5 frequent flyers today. The epic lifts that limit.
A profile can now save more than 5. Airline name and icon come from data
rather than code. The data is shared to verticals. There are two generations
of child stories:

- **Solution stories** (Done, Aug–Sep 2026): [BE] PLAT-59112, [Android]
  PLAT-59749, [iOS] PLAT-60053, [FE] PLAT-60061. Design and documentation
  work. PLAT-59112 adds "searchable functionality when adding frequent flyer".
- **Build stories** (created 2026-09-21): [BE] PLAT-60353, [FE] PLAT-60354,
  [iOS] PLAT-60355, [Android] PLAT-60356. All four share the same requirements:
  1. a profile can add more than 5 frequent flyers;
  2. an existing profile shows at most 5 by default, and a "show all" CTA when
     it has more than 5;
  3. a profile cannot save two frequent flyers for the same airline;
  4. the maximum number of frequent flyers equals the number of available
     airlines.
- Subtasks add the build detail. FE: the collapsed view with "Show all", and
  duplicate validation on both add and edit. Apps: the "Add New" hide-at-5
  logic is removed, a "See All" button opens a frequent flyer list bottom
  sheet, and airline search has found and not-found states.
- **Tech design** (Confluence 4950097948, "Frequent Flyer from Flight Airlines
  Data", last edited 2026-09-25). member-core-v2 `getAirlines` (swagger
  tix-profile-core › Frequent Flyer (B2C Only)) now calls
  flight-master-discovery `GET /tix-flight-master-discovery/airline/findAll`.
  That returns about 1159 airlines with no pagination.
  - **Mapping:** `airlineCode→code`, `airlineName→name`, `icon→icon`.
  - **Cache:** the list is stored in Redis, gzip-compressed, with a 3600 s TTL.
  - **Fallback:** on a flight-master error, the service returns
    `frequent.flyer.airlinesData` from properties. That list has 5 airlines:
    SQ, GA, SJ, QG, TR.
  - **Validation:** the airline-code validation is removed.
  - **New config:** `flightAirlinesDataEnabled` and
    `flightAirlinesDataTTLInSecond`.
  - **Not built:** thundering-herd handling was skipped. Traffic is under
    10 RPM on frequent-flyer/airlines.
  - **Accepted by Product:** an airline change takes up to 1 hour to appear.

## Figma Design Summary

The linked node sits on the **Passenger Data Improvement - Mobile**
page. Screenshots are in `knowledge/evidence/PLAT-60351/`.

- **More than 5** (sticky: "Future case if we can accommodate more than 5
  frequent flyers"). Drawn on Account Details, the main profile.
  - The Frequent Flyer section shows 5 entries, with a **"See all"** link in
    the section header and "Add new" below the list.
  - "See all" opens a **"Frequent Flyer" bottom sheet** with a close (X). It
    lists all entries (6 in the mock, Air Asia being the 6th) and has a primary
    "Add new" button.
- **Detail and edit.** Tapping an entry opens a "Frequent Flyer Details"
  sheet with Airlines and Frequent Flyer Number, plus Delete and Save. The
  **Airlines field is greyed, so the airline looks read-only when editing.**
- **Delete.** The confirmation reads "Are you sure to delete this data?" /
  "When you book for this airline later, you must manually enter the frequent
  flyer number." with "Yes, delete" and "No, cancel". After deleting, the toast
  reads "The frequent flyer data has been deleted."
- **Add.** "Add new" opens a "New Frequent Flyer" sheet (Airlines dropdown,
  number, Continue). The Select Airline sheet has a "Search airline" field and
  radio rows. The search states drawn are Focus, Typing ("S"), Filled
  ("Singapore Airlines", one result) and No Result. Continue shows "Successfully
  added new frequent flyer data.", and the profile's **Save** persists the
  change. Leaving without Save asks "Go to the previous page? …".
- **Not drawn:** a desktop or Responsive version of "See all" (the desktop page
  has no "See all" or "Show all"), the limit state, a missing-icon state, and a
  duplicate-airline error.

## Key Learnings

- **What "config-driven" means here.** The build stories say new airlines
  should come "from config only". The implementation reads airline name and
  icon from **flight-master-discovery**. The properties config is only the
  fallback. PLAT-59112's own wording ("show frequentFlyer data from flight
  datasources") matches the build.  Flight data is the source, with the 5-airline properties list as the fallback.
- **The limit rule is unbuildable on live data.** "Maximum = number of
  available airlines" means about 1159 frequent flyers on live data.
  - A countable airline set is needed to hit the limit. `flightAirlinesDataEnabled=false` *may*
    serve only the 5 property airlines, but the flag's effect is not
    documented.
  - The limit follows from the one-per-airline rule anyway. The real
    regression is a client that still stops at 5.
- **The duplicate rule is FE-only in the written stories.** PLAT-60577
  describes frontend validation. The BE story lists the rule but no BE
  subtask implements it. The airline-code validation was removed, which
  lowers the BE guard.  Whether the API enforces the rule is unconfirmed.
- **Open questions:**
  - Is the one-per-airline rule scoped per profile or per account? Can two
    passengers of one account both have a Garuda Indonesia frequent flyer?
  - Which 5 frequent flyers show when collapsed (sort order)? The design shows
    5 but no rule.
  - Does airline search match by prefix or by substring, on name only or on
    code too? The design's No Result frame types "ine", which a substring
    search would match against "Airl**ine**s", so it suggests prefix matching.
    
  - Can the airline be edited at all? PLAT-60577 says duplicates are blocked
    "during add and edit". The app design greys the Airlines field in Frequent
    Flyer Details. 
  - What placeholder shows when an airline has `icon: null`? In the
    tech-doc sample, 1TIME/RNX has no icon.
  - Which endpoint do verticals read frequent flyers from, and which verticals
    consume them? Only `profiles/b2c` is named, in a traffic note.
  - Can a pre-release app version that capped at 5 overwrite frequent flyers
    6 and later when it saves a profile? The epic does not mention versioning. Ask before release.
- **Fallback risk with no written rule.** During a flight-master outage, the
  picker falls back to 5 airlines. Frequent flyers already saved for other
  airlines then have no name or icon source. No source says how they render.
