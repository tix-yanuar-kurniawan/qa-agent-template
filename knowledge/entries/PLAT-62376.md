# PLAT-62376 — [BE] Handle Extension Points New Logic
> **Related:** [[PLAT-47948]] · [[LoyaltyV1PointExtensionCheckGET]] · [[LoyaltyV1PointExtensionDetailGET]] · [[PLAT-59094]] · [[PLAT-63123]]

## PRD Summary
Reworks the existing Extend Points feature (epic PLAT-47948: revoke expiring
IPC/CASHBACK points, take a configurable fee, re-inject the net as
`points_extended` linked to the original) onto new ULP APIs. Subtasks: outbound
ULP Revoke Calculate and Revoke Lock (PLAT-62495), check API uses ULP calculate
(PLAT-62497), detail page computes fee and final amount (PLAT-62501), extend
action revokes the target point and inserts the new one and returns amount,
total and new expiry (PLAT-62502), reminder cron `POST
/tix-loyalty-core/v1/point-extension/reminder` (PLAT-62505), refund cashback
detail available-point calculation (PLAT-62730), and refund submission switches
to the ULP lock point API (PLAT-62731). Two new edge cases: revoke must touch
only the expiring bucket, and a refund after extension still deducts the
original award (50,000, not the 45,000 left after the fee).

## Figma Design Summary
- Check widget (My Account): "Extend 10,000 points" + "Expired in hh:mm:ss" countdown.
- Detail page: "10,000 points — Ready to be extended", info "Extend your expiring
  points' validity period by 1 month for only a 10% fee", Fee (10%) 1,000 points,
  Amount extended 9,000 points, "Extend points" button, countdown, "Redeem your
  points instead" deals + "See other deals".
- Success bottom sheet: "9,000 points — Successfully extended! Use them before
  30 Nov 2025", "Your current points", vertical icons + "Browse products", deals.
- D-3 email: subject "Only 3 days left! Extend your {expired point amount}
  expiring points now", same fee/amount block, "Points will expire in 3 days".

## Key Learnings
- **The story description is a copy of PLAT-47961** (the original epic's
  "Points extension" story). The "new logic" lives only in the subtask titles
  and the two added edge cases. Read subtasks first on any "[BE] ... new logic"
  story. Case 1's date was corrected (2024 → 2025); everything else is unchanged.
- **ULP API contract is on a separate Confluence page.** PLAT-62495/62497 link a gdncomm
  Confluence page ("Tiket - Lock Revoke Issuance"). Request bodies and error codes of
  the new calls are unknown.
- **Extend page URL disagrees across the old epic:** BE story PLAT-47960 says
  `tiket.com/myaccount/extend-points`, FE story PLAT-47971 says
  `tiket.com/extend-points`.
- **Background vs AC:** the epic background says "recover recently *expired*
  points"; every AC extends points *before* expiry (within the extension period).
- **Refund shortfall is undefined.** If a user extended 50,000 → 45,000 and holds
  nothing else, the refund still needs 50,000.
- **Unstated rules:** minimum inclusive/exclusive, fractional fee rounding, partly
  used bucket amount, whether minimum is per bucket or total, whether
  refund-locked points are extendable, ULP failure handling, repeat-request error
  code.
- Ineligible users get `DATA_NOT_FOUND` from check/detail (vault API notes).
