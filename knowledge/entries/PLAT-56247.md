## PRD Summary
Missions today have no centralized list page — users reach them only through
individually configured entry points such as the homepage banner ([[PLAT-56702]]),
which does not scale and cannot personalize. As Missions move to **segmented
targeting** (CDP / Mixpanel / Dynamic Segment), this epic introduces a **Mission
List Page** at `https://www.tiket.com/id-sg/mission` as the centralized, dynamic
entry point showing every mission a user is eligible for — both **generic**
(all users) and **segmented** (segment members only) — with progress and status.

The page is composed of a BE-configured **banner**, a **user summary stats**
header (Missions Completed, Reward Earned over a rolling 365 days), three
**tabs** — consumer UI **Your Progress / Other Missions / History** (Figma;
maps to API `joined` / `available` / `past`; older AC wording Joined / All /
Past), mission **cards** carrying name, progress, reward type and amount,
reward quota, end date, CTA and rewards icon (list cards reuse the Page Module
shape), dashboard-driven **sort order**, and an eight-state **CTA behavior
matrix** covering guest, B2B, unenrolled with and without prior progress,
enrolled, completed-unclaimed, already-claimed, and ended missions. **Default
tab is conditional** (Figma): Your Progress if the user has joined ≥1 mission,
otherwise Other Missions.

- **Banner language variants are dead scope.** [[PLAT-56343]] (FE) still specifies
  two slots `banner_image_en` / `banner_image_id` and a banner that follows the
  user's active language. [[PLAT-56341]] (BE) was edited **later** — 2026-07-17
  16:38 by the PM, with a matching comment "added req for combining 1 asset for
  both language" — and now reads "1 banner will be used for both EN and ID" with
  the two slots redefined as **Web** and **App**. The FE description has had no
  edits since creation, so its per-language text is stale. The
  "EN banner for EN locale / ID banner for ID locale" pair is dead; the *same*
  asset renders in both languages.
  **Cross-checked against a third story.** [[PLAT-57174]] — the BE half of the
  sibling config epic [[PLAT-57176]] — *also* still specifies `banner_image_en` /
  `banner_image_id` with language-matched serving, but its description was last
  edited 2026-07-17 at **11:54**, under five hours *before* the PLAT-56341 edit at
  **16:38** the same day. The 16:38 text is the newest of all three, so the
  single-asset reading holds and PLAT-57174 is stale on this point too.
  **Corrected 2026-08-12 by [[PLAT-57176]]** — the two slots are **Mobile** and
  **Desktop**, not Web and App. PLAT-56341's body was never re-edited, but
  subtask `PLAT-57731` ("Current Image Config In: EN & ID → To Be Changed to:
  **Mobile & Desktop**", Done 2026-08-06), all three admin API contracts
  (`mobileBanner` / `desktopBanner`) and the shipped Figma (`Mobile Image`
  838×240, `Desktop Image` 1440×484) agree. Web/App is superseded naming for the
  same single-asset decision; the language-variant reading stays dead either way.
  **Resolved:** PLAT-57174 did *not* ship language slots — see [[PLAT-57176]].
  PLAT-57174 is also where the empty-banner behaviour is actually written —
  "if a slot is empty or the asset fails to load → banner is hidden; page still
  loads normally".
- **"Active / Available / Past" is stale tab naming.** [[PLAT-56250]] still uses it
  (and so does [[PLAT-57174]]);
  [[PLAT-56248]] and [[PLAT-56252]] both name the tabs **Joined / All / Past**.
- **The "All" tab definition is resolved by Figma (2026-08-10).**
  [[PLAT-56248]] said All = eligible; [[PLAT-56252]] said eligible but not

  Older AC "Default tab: Joined Missions" is stale for the empty-joined path.

### Feature learnings
- **The story split is BE/FE mirror pairs, not distinct behaviour.** Five of the
  six functional areas exist as a `[BE]` + `[FE]` pair with near-identical ACs
  (Tabs, List Page, Summary Stats, Banner). Only enrollment/reward **idempotency**
  is purely backend, since no UI can express a duplicate-request window.
- **Progress survives non-enrollment, so enrolment must inject it.** Carried from
  [[PLAT-34075]]: unenrolled users still accrue progress from eligible purchases.
  The CTA matrix therefore splits "unenrolled with no progress" (Success Enroll
  bottom sheet) from "unenrolled with ≥1 stamp" (Success Enroll **+ Progress**
  bottom sheet with the prior stamps injected) — the second is the data-loss case.
- **The operator-facing dashboard config is a *different epic* — [[PLAT-57176]].**
  [[PLAT-56250]] talks throughout about "the Mission Dashboard" and an operator
  reordering missions, which reads like Panel scope. It is not: this epic has **no
  `[Panel]` child story**, and every ordering story under it is Backend —
  [[PLAT-57060]] (`PATCH Mission Priority Order` API), [[PLAT-57063]]
  (assign/rebalance function), [[PLAT-56412]] (solutioning, "API tools for sorting
  mission"). The dashboard UI lives under [[PLAT-57176]] *Mission Dashboard –
  Mission List Page Configuration* → [[PLAT-57175]] `[Panel]`, with [[PLAT-57478]]
  (UI, Done) and [[PLAT-57479]] (API integration, TODO). Sorting is
  driven through the priority-order API, and the reorder-from-the-dashboard
  interaction belongs to [[PLAT-57176]].
  **Prose naming an admin surface is not evidence that this epic builds it.**

### Open gaps
- **Tracker events undefined.** [[PLAT-57177]] `[FE] Tracker for Mission List Page` points
  at the *Loyalty Mission Tracker* deck, which was readable but contains only the
  **MVP mission-detail** events (`screenName: loyaltyMission` — pageView, clickTnc,
  clickBack, swipeToJoinMission, clickCollectStamp, successEnroll, seeProgress).
  It defines **no Mission List Page events**. The story is still In Development;
  the list-page tracker spec is not yet available.
- **[[PLAT-56344]]** is a solutioning spike with no acceptance criteria.
- **"B2B state"** of the Mission Detail Page is never defined in the epic.
- **Page Module optional vs list-card reuse (confirmed 2026-08-10).** Mission List
  cards reuse the homepage **Page Module** payload/shape
  ([API Mission List](https://borobudur.atlassian.net/wiki/spaces/PlatTech/pages/4837179528/API+Mission+List):
  "Each mission card reuses the existing page-module shape"). Dashboard still
  treats Page Module as **optional** ([[PLAT-45655]] / [[PLAT-50630]] toggle). When
  a live mission has Page Module **off**, the list still shows the mission but the
  card renders broken (blank white header, truncated copy such as "Rewarc") —
  evidence: `knowledge/evidence/PLAT-56247/2026-08-10-page-module-off-ugly-card.png`.
  **Interim ops rule (until fixed):** anyone enabling/publishing a mission that
  should appear on Mission List **must turn Page Module on** and complete that
  section. **Planned fix (coming sprint):** harden the list/off path; afterward
  the Dashboard Page Module section becomes **mandatory**. Product WIP PRD /
  [[PLAT-56249]] never state this dependency — do not treat "optional Page Module"
  as safe for list-visible missions.
