# PLAT-59157 — Profile - Manage Mononym / Empty Last Name
> **Related:** [[PLAT-59154]] · [[PLAT-59155]] · [[PLAT-59156]] · [[PLAT-59668]] · [[PLAT-59126]] · [[PLAT-57210]]

## PRD Summary

Last name is treated as mandatory today, so a mononym is force-filled as
`lastName = firstName` (booking "Joe" becomes stored profile **Joe Joe**). This
epic adds an empty-last-name checkbox on create/edit of an **additional**
saved-passenger profile so a declared mononym persists as an empty last name
and the saved display matches what the user typed.

The three client stories ([[PLAT-59154]] Responsive, [[PLAT-59155]] iOS,
[[PLAT-59156]] Android) copy the same AC (Ready for QA / Dev Done as of
2026-09-10):

1. Add an empty-last-name checkbox on create/edit of an **additional** profile;
   unchecked by default.
2. Tick → last-name field disabled, emptied, and saved empty. Ticking after the
   field is filled still clears it.
3. Leave unchecked → last-name field stays enabled.
4. Leave unchecked **and leave last name empty** → save is blocked and the
   **current empty-last-name inline error** is shown.
5. Same rules on create and update, all client platforms.

There is no `[BE]` child under this epic. Persistence / no-force-fill lives on
the sibling story [[PLAT-59126]] (Done; no Epic Link) and its Confluence page
[Mononym on profile (empty last name)](https://borobudur.atlassian.net/wiki/spaces/MEM/pages/4921819138/Mononym+on+profile+empty+last+name).
Primary-account mononym via UNM FE, guest booking `fullName: "Joe"`, and admin
search are that ticket — not this one.

  and **Surname/Last Name**, plus a checkbox labelled **No last name/surname**
  (not the story's "Empty last name").
- The block is the component **Section 1 - Account Owner Info**. The list still

- Create entry on the list is **Tambah Data Penumpang**.

- The design does not spell the empty-last-name inline error string; stories

## Key Learnings

- **Requirement 4 flipped after the 2026-09-02 vault note.** That note read
  "leave the checkbox empty but leave the name field" as "save empty last
  name, then re-edit shows the checkbox ticked". As of 2026-09-10 all three
  child stories say save is blocked with the current empty-last-name inline
  error. The child-story AC outranks the epic background ("mononym and empty
  last name is allowed") and the previous vault reading.
- **"The name field" means last name.** Combined with AC 3, last name stays
  mandatory unless the checkbox is ticked. The checkbox is the only way to
  persist an empty last name from this form.
- **The old force-fill is gone.** The background describes today's
  `lastName = firstName`; the new behaviour is the opposite: a ticked
  checkbox saves display `Joe`, not `Joe Joe`.
- **[[PLAT-59126]] is the write contract and it is not a child of this epic.**
  Empty-string last name, "explicit Joe+Joe is kept", "existing Joe Joe rows
  stay until edited", and the out-of-scope list (admin blindIdx, backfill,
  `Joe Madonna` re-split) live there. Guest booking and UNM primary stay on
  that ticket.
- **Stories say additional-only; the design's name block is Account Owner
  Info.** The written AC is that the checkbox is absent on Pemilik Akun. If
  the shared Figma section shipped on the owner form, that needs a PM call. Primary mononym from UNM FE is [[PLAT-59126]].
- **Design copy outranks the story label.** The labels are `No last name/surname` /
  `Surname/Last Name` / `First & Middle Name`; the ID strings and the
  inline-error copy are not specified.
- **FE-only epic, existing form.** No `[BE]` child and no restated
  required-field list on create, so the rest of the passenger form's required
  fields are `UNKNOWN`. Same pattern as [[PLAT-57210]].
