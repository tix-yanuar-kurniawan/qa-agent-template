# PLAT-56907 — [BE] Improve Mission Module on Welcome Rewards
> **Source:** Jira Bug · **Jira:** https://borobudur.atlassian.net/browse/PLAT-56907
> **Related:** [[PLAT-56911]] · [[PLAT-53961]] · [[PLAT-54052]] · [[PLAT-55867]] · [[LoyaltyMissionSlugProgressGET]]

## PRD Summary
Bug fix on top of the Dynamic Missions in Welcome Rewards feature ([[PLAT-53961]]). During testing, clicking "join mission" from the Welcome Rewards (WR) bottom sheet failed to whitelist the user in time, so the user was redirected to a **non-eligible** mission page. The fix moves the whitelist trigger: for **logged-in users** the system whitelists the user on the new user mission **when the WR bottom sheet loads** (no click needed) while keeping the redirect on click; for **non-login (guest) users** the system cannot whitelist on load (Account ID empty) and, because WR is not reloaded after returning from login, the user is whitelisted **on clicking the mission button** and then redirected. `[BE]` / Backend, priority High, status Ready for QA. Related bug [[PLAT-56911]] describes the same fix from the "mission claim error" angle.

## Key Learnings
- **Whitelist timing is the crux of the fix.** Logged-in = whitelist on WR *load*; guest-then-login = whitelist on *click* (WR is not reloaded after the login round-trip, so the load-time whitelist never fires for them).
- A whitelisted-on-load user who simply **dismisses** WR is still whitelisted, which is what lets the **homepage mission entry point** appear afterwards.
- Core requirement: clicking join mission must **never** land the user on a non-eligible mission page.
- Whitelist/eligibility call carries **Mission ID + Account ID** and covers **all** missions in the selected config (inherited from [[PLAT-53961]] auto-eligibility), not just the tapped one.
- Precondition throughout is a **never-transacted** account (the "new user mission" targeting); a transacted user should not be whitelisted.
- Guest path still routes clicks through **Login/Register** (from [[PLAT-53961]] AC), then whitelist+redirect on the post-login click.
- The feature ships on iOS + Android apps.
