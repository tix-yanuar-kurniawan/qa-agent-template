# PLAT-63123 — [BE] Supporting Insurance Claim to Points
> **Related:** [[PLAT-62625]] · [[PLAT-59094]] · [[PLAT-62376]]

## PRD Summary
Insurance is building claim payout to Blibli Tiket Points (epic PLAT-62625,
"One Tap Claim to BTP via WhatsApp", phase 1 Flight Disruption). Loyalty must
accept the injection. Rules: new point type / ACTION_CODE `INSURANCE_CLAIM`
(subtask PLAT-63764); Loyalty sends no notification when these points are
injected; they cannot be injected from the Loyalty Dashboard in Admin Care; they
can be deleted from the Tech Support Dashboard for customer complaints.

## Key Learnings
- **The story names no endpoint.** Which Loyalty API Insurance calls, its body,
  and the claim reference field are all unspecified. The Insurance FE story (PLAT-62627) is Blocked, so no UI
  path triggers the injection yet.
- **Claim amount → points conversion is Insurance's**, not this story's.
- **Not stated:** duplicate injection for one claim, how Admin
  Care blocks the type (hidden vs rejected), Tech Support Dashboard path,
  earn_source for FDS, INSURANCE_CLAIM expiry rule.
- **Cross-flow with PLAT-59094:** every credit sends `loyalty_points_earned` to
  FDS with `point_type`; a new type needs an `earn_source` mapping nobody
  specified.
- **Cross-flow with point extension (PLAT-62376):** a new point type is
  extendable only if added to the eligible list.
- **Admin Care restriction must be type-specific:** it must not block other point types.
